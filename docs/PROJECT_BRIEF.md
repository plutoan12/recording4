# 프로젝트 범위

## 목표

원본 영상을 다른 언어의 더빙·자막 영상으로 만들고 사람이 검수한 버전만 YouTube에 예약 공개합니다. 실패한 단계부터 다시 실행하고, 작업·비용·승인 이력을 추적할 수 있도록 합니다.

## 사용자 요청으로 확정된 사항

- GitHub, 영상 저장소, AI API, 영상 서버, 관리화면, YouTube를 연결하는 구조를 계획합니다.
- 현재 산출물은 구조·기술 선택·구현 계획 문서입니다.
- Codex와 Claude가 협업할 수 있도록 문서를 GitHub에 보관합니다.

## 제안하는 MVP

- 관리자 로그인, 원본 등록, 작업 목록과 진행 상태.
- 시간 정보가 있는 STT 대본, 번역 편집, 문장별 더빙.
- FFmpeg 영상·음성·자막 합성, 결과 미리보기.
- 결과물 버전별 승인 및 재검수.
- 승인된 영상의 YouTube 업로드와 공개 예약.
- 단계별 재시도와 작업 로그.

립싱크는 초기 샘플 평가 후 확장 단계에서 추가하는 제안입니다. 사용자가 최종 확정한 제외 항목은 아닙니다.

## 초기 설계 가정

- 관리자 1명, YouTube 채널 1개, 작업별 대상 언어 1개.
- 원본은 사용자가 파일로 등록합니다. 외부 영상 자동 수집은 포함하지 않습니다.
- AI는 외부 API를 우선 평가합니다. 초기 자체 GPU 운영은 가정하지 않습니다.
- 공개 시각은 관리화면에서 Asia/Seoul로 입력·표시하고 내부에는 UTC로 저장합니다.

## 구현 전에 확인할 사항

| 질문 | 영향 |
|---|---|
| 원본·대상 언어, 화자 수, 대표 영상은? | STT·더빙 모델, 화자 처리 |
| 월 영상 수, 평균·최대 길이와 해상도는? | 처리량, 파일 제한, 서버 사양 |
| 월 예산과 허용 처리 시간은? | API, 워커 수, 재시도 한도 |
| 립싱크가 필수인가? | MVP 범위와 비용 |
| 배경음·효과음 별도 트랙이 있는가? | 음원 분리 필요성 |
| 기본 제공 음성인가, 사용 허가를 받은 복제 음성인가? | 음성 공급자·입력 요구사항 |
| 저장소·서버·Google/YouTube 계정이 준비되어 있는가? | 연결과 배포 일정 |
| 원본과 중간 파일을 얼마나 보관할 것인가? | 저장 비용과 삭제 정책 |
| 월·작업당 비용 상한 금액은? | 유료 호출 차단 기준, 재시도 한도 |
| 더빙 길이 허용 오차를 어디까지 둘 것인가? | 구간 겹침 허용 수준, 재생성 비용 |
| 원본 삭제 요청 시 게시된 영상도 내릴 것인가? | 삭제 정책, 감사 기록 범위 |

## 비용 산정 방식

월 원본 분량 = 영상 수 × 평균 길이. 대상 언어별 더빙·합성 비용과 립싱크 적용 분량을 별도 계산합니다. STT는 같은 원본에 대해 재사용하도록 설계합니다. 저장 용량·전송량·재생성 횟수·서버 실행 시간을 추가합니다.

현재 처리량과 API 모델이 미정이므로 고정 금액이나 완료 날짜는 확정하지 않습니다. 대표 영상의 실제 실행 결과로 영상당 비용과 소요 시간을 먼저 측정합니다.
