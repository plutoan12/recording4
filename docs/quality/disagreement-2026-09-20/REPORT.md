# 화자 불일치 검수와 DiCoW 비교 (2026-09-20)

사용자가 선택한 네 단계 중 **불일치 검수와 겹말 재인식 비교를 구현·실측했고, 누락 진단을 수행했다.** 네 언어 새 실제 대화 검증은 아직 완료되지 않았다. 운영 자동 수정/모델 교체는 하지 않았다.

## 1. 기존 모델과 Sortformer 대조

- `pipeline.speaker_disagreement.compare_turns`는 정답 없이 두 예측의 시간 겹침으로 익명 화자를 일대일 대응한다. 동점·근거 없는 대응을 확정하지 않고 불확실로 표시한다. 발화 유무/화자 수/대응 차이를 구분하며 겹말과 중복 같은 화자 트랙을 보존한다. 최대 모델당 8명 지원.
- `mark_reviews`는 구간 및 단어의 `needs_review`와 이유만 추가하고 대사·시각·기존 화자를 바꾸지 않는다. `compare_diarizer_reviews.py`는 동일 음원 SHA를 요구하고 비공개 새 결과를 저장한다. 관리화면/운영 워커에 자동 적용한 것은 아니다.
- `overlap_retry_windows`는 겹말이 의심되는 **불일치**만 양옆 0.5초 문맥과 함께 선택하고 최대 30초로 분할한다. 문맥 확장은 평가 오차 허용치를 바꾸는 것이 아니다. 선택된 18개 창은 후속 국소 재인식 후보이며 이번 DiCoW 점수의 분모로 사용하지 않았다.
- 같은 11조건/4,389자에서 기존 정답/오배정/미확인 **3767/109/513 그대로**, 자동 배정 변경 0. 오배정 **109자 모두** 추가 비교 표시 대상에 포함됐다. 맞는 글자 **212자(3767자의 5.63%)**, 미확인 180자도 표시됐다. 이것은 해당 제어 표본의 검출 결과이며 일반 검출률 100% 또는 정답 향상이 아니다.
- 새로 검수 표시된 단어 74개(50% 두 조건에서 33개). 정상 발화 경계 차이도 표시되므로 검수 부하와 놓친 오류를 함께 평가해야 한다.

## 2. DiCoW 겹말 재인식 — 유료 GPU 없이 완료

Docker 밖의 별도 Mac CPU 환경에서 기존/후보 마스크를 **동일 float32**로 4개씩, 총 8개 실행했다. 종료 코드 0, EOS 종료 8/8, 새 유료 호출 0.

| 제어 조건 | 기존 화자 마스크 + DiCoW | Sortformer v2.1 마스크 + DiCoW |
|---|---:|---:|
| 25% 겹말 | 2/399자 오류 (0.50%) | 3/399자 오류 (0.75%) |
| 50% 겹말 | 159/399자 오류 (39.85%) | 6/399자 오류 (1.50%) |

- 같은 원본/정답/예측 마스크, CTC0/greedy/max200. 모델 리비전 `00a09c622bf58c34fdc76c3b5676f4da706f2a8e`. 익명 화자-정답 대응은 평가용이며 모델에 정답 마스크/대사를 넘기지 않았다.
- CPU torch2.14.0, transformers4.42.4/tokenizers0.19.1/accelerate0.33.0, numpy1.26.4. Docker 때의 INT8 결과와 직접 향상률을 비교하지 않는다. 양쪽을 같은 Mac float32 환경에서 새로 실행했다.
- `scripts/run_dicow_native.py`에 재현용 실행 경로를 추가했다. 별도 Python/호환 의존성 경로를 명시하고 새 비공개 결과 폴더/제한 시간/상태 파일을 사용한다. 생산 토큰 환경변수를 물려주지 않는다. 이번 실제 실행은 같은 `benchmark_target_asr.py`를 직접 호출했으며 새 래퍼 자체의 전체 모델 재실행은 반복하지 않았다.
- 이전 Docker 종료137은 그대로 실패 기록으로 남긴다. Mac 성공은 원인을 OOM으로 확정하는 증거는 아니지만, 이번 비교를 위해 GPU 결제가 필요하지 않다는 것을 확인했다.
- 이는 **겹말 제어 음원 대사 인식 CER 개선**이다. 실제 대화 전체, 네 언어, 화자 문자 정확도, 음질 향상이나 자동 승인으로 확대 해석하지 않는다. 25% 악화가 남아 일괄 교체하지 않는다. 국소 창별 대사 평가/독립 음성·시각 근거 연결도 남아 있다.

## 3. 발화 누락 진단

`diagnose_diarization_misses.py`는 고정 20ms 원음 RMS 층과 사람 정답 발화 길이/겹말 여부로 누락을 나눈다. 모델 경계를 바꿔도 음향 층의 분모는 동일하다. 누락 시간은 기존 DER의 missed detection과 일치한다. 혼합 음원의 RMS는 개별 화자 SNR이 아니며 인과 판정은 하지 않는다.

| AMI 구분 | 분모(화자·초) | 기존 누락 | Sortformer v2.1 누락 |
|---|---:|---:|---:|
| 전체 | 38.92 | 7.4365 | 18.91 |
| 한 명 발화 | 32.38 | 5.4394 | 14.59 |
| 겹말 | 6.54 | 1.9971 | 4.32 |
| 활동 중인 발화가 모두 0.5초 이하 | 2.40 | 1.3207 | 0.73 |
| 0.5초보다 긴 발화 포함 | 36.52 | 6.1158 | 18.18 |
| 혼합 RMS -40dBFS 미만 | 32.71 | 6.3978 | 16.48 |

짧은 맞장구는 오히려 덜 놓치므로 그 문제만 고쳐 전체 누락을 해결한다고 볼 수 없다. 낮은 음량 층이 원래 분모 대부분(32.71/38.92)을 차지하므로 “누락 대부분이 조용함”만으로 원인을 단정하지 않는다. 모델 개선/음량 처리/임계값 조정은 독립 개발 표본에서 검증한 후 평가해야 하며 이번 AMI 결과에 맞춰 튜닝하지 않았다.

## 최종 코드 검토

Claude 읽기 전용 검토 후 검수 입력에도 같은 음원 SHA를 요구하고 선언된 duration 불일치를 거부했다. CLI의 reviews 입력은 `{"source_sha256":"…", "reviews":[…]}` 형태다. 재비교 시 이전 model_disagreement_reasons는 지우되 기존 needs_review는 유지한다. 공개 실측은 변경 전 저장 예측에서 같은 음원을 직접 연결해 계산했으며 이 입력 방어로 모델 추론/점수는 변하지 않는다.

검토에서 제기한 화자 수 차이와 배정 집합 차이는 중복 사유를 허용하는 현재 의미를 유지한다(독립 근거 두 개로 세지 않는다). 진단 도구의 최대 8화자/양수 구간 제약과 프레임×구간 비용은 현재 짧은 실험 범위의 제한으로 남는다. 0길이 구간을 자동 허용하지 않는다. 국소 창의 문맥은 원래 intervals와 별도이며 창 전체를 감지된 겹말로 세면 안 된다. 이 실험 도구는 장시간 운영 입력을 처리하도록 승인되지 않았다.
