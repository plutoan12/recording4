# 긴 문맥 재인식과 이중 시각 정렬

기존6구간/115자/48평가칸을 유지하고 앞뒤3초씩 더 들려주는30개 DiCoW 디코딩과30개 정렬 판정을 완료했다. **운영 채택 보류**다. Sortformer 입력의 편집 오류는 줄었으나 올바르게 맞춘 글자도 줄었다. 이를 대사 복구나 전체 정확도 개선이라고 주장하지 않는다.

## 변경과 고정 조건

- `prepare_dicow_context.py`는 원래 start/end를 core_start/core_end로 보존하고 추가3초씩을 인식에만 사용한다. 원문 정답으로 경계를 바꾸지 않는다. 고정115자와 경계에 걸친11단어를 그대로 평가한다.
- 같은 CPUfloat32 DiCoW 모델/CTC0/beam1/최대200토큰을 사용했다.30/30정상종료, 최대길이도달의심0. 원래6개 핵심구간의 결과를 비교하며 길어진구간 자체의 정답으로 분모를 늘리지 않았다.
- `align_dicow_context.py`는 DiCoW가 생성한 대사만 stable-ts/WhisperX에 주고 시각을 붙인다. 정답 대사는 정렬 입력에 없다. 정렬된 대사가 전체 생성문을 보존하는지 확인하고, 두정렬기가 핵심구간과 겹친다고 판단하면서 양끝시각 차이가 기존기준0.5초 이내인 단어만 추출한다. 토큰 분할이 다르면 정규화글자 위치로 비교한다.
- 두시각의동의는 화자신원이나 대사의진실성을증명하지않는다. 정렬실패/불일치면 기존짧은결과를그대로보존하고 실패로기록한다. 문맥부분 대사를 기존자막에중복삽입하거나 화자표시를수정하지않았다.

## 실제 결과

| 방법 | 짧은 구간 → 긴 문맥+정렬 |
|---|---:|
| Community 입력 편집 오류 | 75 → 77 |
| Sortformer 입력 편집 오류 | 106 → 97 |
| Community 입력 일치 글자 | 56 → 44 |
| Sortformer 입력 일치 글자 | 25 → 18 |
| Community 입력 삭제 오류 | 35 → 56 |
| Sortformer 입력 삭제 오류 | 83 → 90 |
| Community 입력 전체 삽입 오류 | 16 → 6 |
| Sortformer 입력 전체 삽입 오류 | 16 → 0 |

양쪽모두 빈정답화자에대한삽입은0이됐다(전체삽입과다른지표). 하지만 놓친대사를회복하지못하고 삭제가늘었다. 특히Sortformer의9오류감소는 올바른대사증가를뜻하지않는다. 편집정렬의일치글자는단어/화자정답률과구분한다.

정렬판정30개: 시각동의12, 생성문빈결과5, 기존결과유지13(시각불일치6/핵심구간포함판단불일치4/잘못된시각3). 빈출력5개를정렬성공으로세지않는다. 자동자막/화자변경0. 서로다른방법/정렬결과의좋은부분만골라성공으로표시하지않는다.

## 실행/검증

처음정렬호출은잘못된word_timings모듈경로에서중단돼수정했다. 이어오프라인환경의NLTK punkt_tab누락을공식nltk_data자료로보완했다. 다운로드SHA는results.json에기록했다. 이후NLTK_DATA를비공개평가폴더로지정해 네트워크차단컨테이너/읽기전용모델캐시/CPU2/메모리6GiB에서정렬30개를완료했다. DiCoW추론결과는재사용하여이문제로재추론하지않았다. 운영워커/시크릿은수정하지않았다.
