# 원문 말투 유지·문체 검수 및 싱크 조건 확장

## 사용자 선택과 구현

사용자는 **원문의 말투 유지, 문체 혼용만 검수 표시**를 선택했습니다. 자동 문체 변환·새로운 번역 API 호출을 추가하지 않았습니다.

- 작업 상세 조회 시 현재 원문/번역에서 문체 단서를 읽고, 혼용 가능성이 있으면 관리화면에 문체 종류와 해당 자막 번호를 표시합니다. 기존 작업에도 적용됩니다. 원문, 번역, 시각, 승인 상태는 바꾸지 않습니다.
- 한국어 합니다체/해요체/비격식 서술체, 일본어 です・ます체/보통체, 영어 일부 명시적인 격식/구어 표현, 중국어 일부 정중/구어 표현을 검사합니다.
- 인용부호로 묶인 말은 제외합니다. 화자 전환이나 원문의 의도일 수 있으므로 오류로 단정하거나 승인을 차단하지 않습니다. 영어·중국어는 특히 제한된 단서 검사이며, 표시가 없다고 문체가 완전히 일관된 것은 아닙니다.
- 검수 편집기에 자막 번호를 추가하고, 자막 전용 작업의 수정 버튼이 더빙을 한다고 표시되던 문구를 바로잡았습니다.

## 싱크 검증 자료와 방식

기존 3문장과 다른 공개 Bingsu/zeroth-korean test 자료를 시작 행 30부터 9개 받아 사용했습니다. 사람 녹음에서 얻은 깨끗한 기준 시각을 유지하며 발화 간격·속도·음량·잡음을 바꿨습니다. 각 조건은 실제 AAC/MP4로 인코딩해 워커의 음성 추출과 ffsubsync를 통과합니다.

**현장 촬영 영상 10편을 수집한 검사는 아닙니다.** 실제 한국어 음성으로 만든 통제된 테스트 영상입니다. 긴 영상은 같은 9문장을 세 번 반복했고, 배경 음악은 합성 화음, 잡음은 고정 시드로 만든 잡음입니다. 일본어·중국어·영어 발화, 겹치는 대화, 자연 촬영 잡음과 장시간 콘텐츠는 검증 범위 밖입니다.

판정은 이동 0초(이미 맞는 자막)와 +2.5초 각각에서 **시작·끝 최대 오차와 이동값 오차 0.5초 이하**, 문장 수와 글자 보존입니다. 부동소수점 연산 오차만 1e-9초 허용하며, 0.5001초는 실패하는 테스트로 고정했습니다. 실패나 거부를 통과로 세지 않습니다.

## 새로 발견해 수정한 문제

ffsubsync가 긴 입력 자막을 내부적으로 최대 10초로 줄인 파일을 출력해, 영상과 시간 이동값이 맞아도 자막 끝이 일찍 사라졌습니다. 이전 검사는 시작 시각 중심이라 놓쳤습니다.

프레임률 조정이 꺼진 기본 모드는 원래 시작·끝에 계산한 이동값만 더하도록 수정했습니다. 원래 문장 길이와 글자는 보존하고, 음수 시각·한도 초과·문장 수 변경 방어는 유지합니다. 프레임률 조정을 명시적으로 켠 경우에는 기존 동작을 유지합니다.

수정 전 20개 검사 모두 끝 시각 오류 또는 밀리초 반올림 영향으로 실패했고 최대 오차는 4.759초였습니다. 수정 후 같은 자료·기준으로 **20/20 통과**했습니다. 빠른 말은 0.50초로 기준 경계이므로 여유가 크지 않습니다.

| 조건 | 길이(초) | 원래 자막 최대 흔들림(초) | +2.5초 복구 최대 오차(초) |
|---|---:|---:|---:|
| 짧은 영상 | 36.24 | 0.40 | 0.40 |
| 반복 구성 긴 영상 | 276.31 | 0.03 | 0.03 |
| 짧은 발화 간격 | 85.12 | 0.03 | 0.03 |
| 긴 무음 간격 | 128.77 | 0.03 | 0.03 |
| 1.25배 빠른 말 | 74.22 | 0.50 | 0.50 |
| 0.8배 느린 말 | 115.96 | 0.03 | 0.03 |
| 음량 -18dB | 92.77 | 0.06 | 0.07 |
| 잡음 SNR 15dB | 92.77 | 0.00 | 0.00 |
| 잡음 SNR 5dB | 92.77 | 0.04 | 0.04 |

- [수정 전 측정](before.json), [수정 후 측정](after.json)
- 전체 Python 테스트 **399 통과, 5 조건부 skip**, TypeScript·Vite build·Ruff 통과.
- 실제 HTTP API에서 합니다체/서술체 혼용 안내와 자막 글자 불변을 확인했습니다. Mac 잠금 때문에 브라우저의 실제 화면 확인은 아직 하지 못했습니다.
- 새 유료 API 호출이나 YouTube 업로드는 하지 않았습니다. 음성·영상 원본은 저장소에 커밋하지 않습니다.

## 재현

워커 이미지의 Python·FFmpeg·numpy·ffsubsync를 사용합니다.

```sh
python scripts/fetch_korean_speech.py --out /corpus --count 9 --offset 30
python scripts/verify_sync_matrix.py --directory /corpus --out /results --limit 0.5
```

문체 검수는 번역 후 반드시 내용을 읽고 판단해야 합니다. 자막이 서로 다른 화자의 말투를 충실히 옮긴 것이라면 혼용 안내가 있어도 고치지 않는 것이 맞습니다.
