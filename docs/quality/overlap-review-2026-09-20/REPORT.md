# 단어별 화자 배정·겹말 검수 구현 및 같은 11조건 비교

## 변경

- 겹말이 감지되거나 정렬 근거가 부족하면 `needs_review`를 기록하고 관리화면에 **검수 필요**를 표시합니다.
- 원문 대본을 자막별로 정밀 정렬하고 단어 시각별 후보 화자를 확인합니다. 여러 후보가 걸리는 단어는 **복수 화자**, 근거가 없는 단어는 미확인입니다. 문장 전체의 최장 겹침 화자를 강제로 선택하지 않습니다.
- 문구·문장 시각은 보존합니다. 단어별 결과는 MediaTask 결과에 저장하고 새 대본 버전에 연결합니다. 원문과 정렬 문구 불일치, 범위 밖/역전 시각, 정렬 실패는 배정 근거로 사용하지 않습니다.
- 분석 시작의 대본 버전·원문 언어를 고정합니다. 처리 도중 대본이 바뀌면 새 결과 저장을 중단하며 구버전 분석을 현재 버전에 표시하지 않습니다.
- 복수 화자는 실제 사람 한 명으로 집계하지 않으며 단일 화자 배정 완료 수에도 포함하지 않습니다. API 작업 성공은 처리 완료이지 검수 통과가 아닙니다.

## 같은 입력 비교

[이전 11조건](../diarization-stress-2026-09-20/REPORT.md)의 WAV를 그대로 재사용했습니다. 각 SHA-256을 이전 보관본과 비교했고 파일은 변경하지 않았습니다. 화자 모델·힌트 없음·CPU 조건은 그대로이며, 원본 네 발화의 실제 영어 문구를 정렬에 사용했습니다. 새 문구 전사나 유료 API는 호출하지 않았습니다.

화자 수/겹말 검출 자체는 바꾸지 않았습니다. 이번 평가는 **단어 시각을 이용한 배정과 불확실성 표시**입니다. 각 발화의 알려진 원 화자와 비교하며, 라벨 순열은 같은 에너지 활동 기준으로 맞춥니다. 수동 타임스탬프 DER은 아닙니다.

문장과 단어를 비교하므로 공백을 뺀 원문 문자 수(조건당 399자)로 동일 분모를 사용합니다. `복수 화자`·미확인·정렬 실패는 정답으로 계산하지 않습니다. 단어의 시각이 틀려 다른 화자로 배정돼도 오배정으로 집계합니다.

총 4,389자에서 오배정은 **344→109자**, 정답은 **4,045→3,069자**, 미확인은 **0→1,211자**입니다. **오배정은 줄었지만 자동 정답 범위도 감소했습니다.** 전반적 정확도 향상 또는 겹말 해결 완료라고 표현하면 안 됩니다.

- 깨끗한 기준과 20/10 dB 잡음 5조건: 정답 399/399 유지, 불필요한 검수 없음.
- 0 dB 잡음 2조건: 정렬 검증을 못 통과한 한 문장씩(188자)이 검수로 남는 회귀/적용 범위 감소가 있습니다.
- 25% 겹말 2조건: 기존 문장 화자는 맞았어도 단어별 확신이 부족한 226자를 미확인으로 남깁니다.
- 50% 겹말: 오배정 172→56자, 잡음 포함 172→53자. 두 조건 모두 4문장 전체를 검수 대상으로 표시하지만 일부 단어의 오배정은 여전히 남습니다.

## 검증과 재현

- Python 전체: 448통과/5조건부 skip, 로컬 포트 제한 4개는 권한 있는 환경에서 별도 재실행해 모두 통과(합계 452통과). 후속 API 수정 관련 12개 재검사 통과.
- Ruff·관리화면 TypeScript/Vite 빌드 통과. 겹말/순차 화자 변경, 잘못된 단어 정렬, 동일 화자 중복 구간, DB/API 검수 보존, 대본 수정 중 결과 차단을 검사했습니다.
- `python scripts/verify_overlap_review.py --directory <원본 mono-*.wav와 expected.json> --fixtures <이전 11개 WAV와 metrics.json> --output <비공개 결과 폴더>`
- 정량 결과는 `comparison.json`. 단어별 공개 원문을 포함한 상세 결과와 음원은 `.runtime/overlap-review-20260920`에 보관하고 GitHub에 올리지 않았습니다.
- 실제 주관적 음질 청취는 이번 범위가 아니며 이전 미완료 상태를 유지합니다.

Mac에 API·워커·관리화면 이미지를 반영했고 API/워커 healthy, 배포된 API/워커 파일 해시 일치 및 `A → 복수 화자 → B` 단어 검수 스모크를 확인했습니다. 브라우저 실제 화면 직접 검증은 하지 않았습니다.
