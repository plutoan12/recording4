# 검수 후보·품질 판정 자동화

## 완료한 자동화

`automate_speaker_review.py`가 같은 음원 SHA와 문자 분모를 확인하고, 품질 판정 → DiCoW 대사와 기존 단어의 검수 후보 연결 → 요약 저장을 한 번에 수행합니다. 운영 자막·원음·화자 라벨·단어 시각은 바꾸지 않습니다.

- 품질 판정: 표본 누락/중복, SHA 변경, 분모 변경, 음수/비정수 수치를 차단합니다. 조건별 정답 감소 또는 오배정 증가도 거부합니다. 전체 정답이 늘지 않은 동률도 채택하지 않습니다.
- 결과가 좋아도 `improved_on_this_corpus`일 뿐이며 `deploy_allowed=false`입니다. 새 실제 대화 검증과 운영 연결은 별도입니다. 종료 코드 0은 해당 자료의 개선, 2는 유효하지만 채택 불가, 1은 잘못된 입력을 뜻합니다(`check_speaker_quality.py`).
- 검수 후보: 12자 이상 일치하는 문구 안의 단어만 연결합니다. 실제 겹말·유효한 시각·원문 정렬 일치를 요구합니다. 양쪽 대상 화자의 대사가 같은 문구를 포함하면 복수 후보로 남깁니다. 단어의 기존 화자는 유지합니다.
- DiCoW는 예측 화자 구간에 조건화되어 있으므로 독립 목소리 근거가 아닙니다. 독립 근거 파일을 주지 않은 기존 실행의 후보는 `independent_voice_verified=false`, `applied=false`로 저장합니다. 후속 계약에서는 같은 음원·단어에 묶인 별도 음성·시각 근거가 모두 통과할 때 검수 자격만 true가 될 수 있지만 `applied=false`와 기존 화자는 유지합니다. 원래 정답 대본은 후보 화자 결정 입력이 아니며 실제 모델이 출력한 대사를 비교합니다. [후속 계약](../target-independent-evidence-2026-09-20/REPORT.md).
- 동일 입력을 재실행할 때도 시작 시 완료 표식을 무효화합니다. 중간 실패를 이전 성공으로 잘못 읽지 않도록 합니다. 원시 후보 대본은 비공개 runtime에만 저장하고 공개 보고서에는 건수·해시만 둡니다.

## 실제 실행

기존 11조건은 3,767/109/513(정답/오배정/미확인)으로 동일하여 품질 판정은 `reject: no_additional_correct_assignments`입니다. 기존 오배정 109자는 수정되지 않았습니다.

저장된 DiCoW 결과를 연결한 검수 후보는 25% 겹말 12단어, 50% 겹말 36단어로 총 48단어입니다. 이 숫자는 정답 증가나 오배정 수정 수가 아닙니다. 실제 변경은 0입니다. 잡음 포함 겹말의 DiCoW 결과는 아직 없으므로 그 조건에는 후보를 만들지 않았습니다.

## 중국어 표기 별도 검사

공식 [OpenCC](https://github.com/BYVoid/OpenCC)의 `opencc==1.4.2`, `t2s.json`을 별도 환경에 설치했습니다. 기존 새 중국어 낭독 3개, 121자에 대해 인식 결과만 간체로 변환하고 원래 참조는 유지했습니다. 이전 보고서의 raw CER은 덮어쓰지 않습니다.

| 모델 | 기존 오류 | 간체 출력 후 오류 | 간체 출력 후 CER |
|---|---:|---:|---:|
| Whisper small | 20 | 5 | 4.13% |
| DiCoW INT8 | 44 | 20 | 16.53% |

이는 결과를 본 뒤 추가한 탐색 검사이며 처음 표는 기존 자료를 재사용한 결과입니다. 음성 인식 모델 자체가 좋아진 것도 아닙니다. 중국어 전체에 간체를 강제하지 않고, 향후 자막 출력 표기(간체/번체)를 사용자가 선택하는 경로의 근거로 보관합니다. 운영 의존성·출력은 변경하지 않았습니다.

### 선택에 쓰지 않은 새 중국어 낭독

위 설정을 정한 뒤 FLEURS 동일 리비전의 앞 60개를 제외한 다음 3개를 별도로 받았습니다. Whisper small의 104자 중 raw 오류 31자(29.81%) → 간체 출력 후 4자(3.85%)였습니다. 음성 인식은 새로 실행했고 이전 3개와 다른 원본 SHA를 확인했습니다. 결과/출처는 `chinese-holdout.json`, `chinese-holdout-source.json`입니다. 실제 중국어 대화나 고유명사 전반을 보장하는 결과는 아닙니다.

## Claude 검토 반영

- 오디오 크롭 이후의 패딩은 STNO silence로 강제합니다. 기존 16개 표본은 모든 예측 구간이 실제 음원 안에 있어 이전 입력 마스크가 바뀌지 않음을 확인했습니다.
- Linux 전용 `malloc_trim`은 선택적인 메모리 정리로 바꾸고, 다른 실행 설정으로 기존 결과 파일을 덮어쓰지 못하게 했습니다. 생성 길이 제한에 걸렸을 가능성도 별도 기록합니다.
- `stage 3 + reconsider` 같은 무효 조합은 거부합니다. 유효하지 않은 단어 시각으로 기존 화자를 재배정하지 않으며, 원문/길이 불일치 거부 사유를 기록합니다.
- 과거 문장 배정도 미확인 판정을 동일하게 적용합니다. 원본 발화·잡음 시드·혼합 방식으로 11개 WAV의 PCM을 재생성해 실제 입력과 일치하는지 확인했습니다.
- 기존 통제 검사는 **정답 문구와 정답 발화 경계**를 정렬 입력으로 사용합니다. 예측 화자 마스크는 정답으로 바꾸지 않습니다. 운영 STT의 문구·경계 오류까지 포함한 종단 성능으로 해석하면 안 됩니다.
- 분리 채널 경계의 cross-fade와 채널 순열 점수 보정은 아직 실험 과제입니다. 별도 의존성으로 분리된 실험 코드를 운영 정확도 보장으로 취급하지 않습니다.

## 재현

```sh
PYTHONPATH=services/worker:services/api:packages/pipeline python scripts/automate_speaker_review.py \
  --baseline docs/quality/speaker-diagnostics-2026-09-20/regression.json \
  --candidate .runtime/speaker-reconsider-approved/comparison.json \
  --reviews-dir .runtime/speaker-reconsider-approved \
  --predictions .runtime/dicow-overlap-checked/results.json \
  --manifest .runtime/dicow-overlap-manifest.json \
  --output .runtime/target-review-automation
```

현재 자료에서 종료 코드 2가 정상적인 채택 거부 결과입니다. 이 명령은 이미 생성된 모델 결과를 평가·연결합니다. 새 음원의 모델 추론, 관리화면 검수 버튼, 자동 배포·게시까지 실행하는 명령은 아닙니다. 기존 manifest/예측 결과의 화자 대응을 유지해야 하며 검수 후보를 자동 수정 근거로 승격하면 안 됩니다.

## 재검토 후 추가 차단

Claude 후속 검토에서 지적한 누락/잘린 대상 화자 결과를 막았습니다. 모든 예상 화자의 결과와 정상 종료 메타데이터가 있어야 후보를 만들며, 알 수 없는 조건 ID는 무시하지 않고 거부합니다. 기존 결과 덮어쓰기 가능성은 추론 전에 전체 입력을 점검해 차단합니다. 단어별 화자·문구·시각의 전후 일치도 실제 비교합니다. 음원 생성과 검증은 동일한 `render_case` 함수를 사용합니다.

종료 정보가 없던 기존 결과는 그대로 재사용하지 않고 겹말 4건을 새로 추론했습니다. 모두 정상 종료했고 CER은 25% 6/399, 50% 126/399로 같았습니다. 갱신된 후보도 48단어, 변경 0, 품질 판정은 정답 미증가로 거부입니다. 공개 수치는 `dicow-checked.json`에 있습니다. 전체 Python **486통과/5skip**, 변경 파일 Ruff 통과.
