# 공백 포함 CJK 단어 경계 복구

화자 검수는 정렬기가 반환한 단어 글자를 원래 자막 안에서 다시 찾아 시각과 화자를 붙인다. 기존 규칙은 자막에 공백이 둘 이상 있으면 정렬 단위도 공백 경계와 정확히 같아야 했다. 중국어·일본어 정렬기는 한자·가나를 더 작은 조각으로 반환하므로 실제 시각이 있어도 대부분 미확인으로 버렸다.

## 고정 실제 대화

기존 비공개 다국어 실제 대화에서 한·일·중·영 각 4구간을 추론 전에 고정했다. 중국어와 일본어 대본에는 글자를 바꾸지 않고 4~5자마다 공백을 넣어 사용자가 구 단위로 띄어 쓴 자막을 재현했다. 한국어는 제공자 대본의 원래 공백을 유지했고, 영어는 공식 AMI 단어 전사에서 같은 구간을 만들었다.

- 정렬기: `stable-ts 2.19.1`, `Systran/faster-whisper-small`, CPU int8
- 입력 파일 SHA-256: `ccc656a834bba67ab715bbe11a07a9059d529f3c1aec691d485ea6e80382e600`
- 정렬 결과 SHA-256: `1c8e7c4c4acce8a7a25f49417689127d98d8504108671fe840b288a132e796dd`
- 최종 matcher 소스 SHA-256: `3b2cdb24595959dbf4d4a1aa4cbddf43672f302b23d6cd9fbd32d521bb197bb0`
- 최종 재측정 파일 SHA-256: `d63c826d9157a33a10709648b19e361a0feb00a9cd3ad2643d28b56ccc219843`
- 원음·대본·단어 시각: 비공개 `cjk-boundary-20260920`

## 결과

`유효 시각 문자`는 정렬 결과의 글자가 원래 대본의 순서와 경계를 통과해 화자 배정 단계까지 보존된 문자 수다. 정렬기 자체가 시각을 만들지 못한 문자는 회복으로 세지 않았다.

| 언어 | 구간 | 대본 문자 | 기존 유효 시각 | 변경 후 유효 시각 | 변화 |
|---|---:|---:|---:|---:|---:|
| 중국어 | 4 | 110 | 2 | 99 | +97 |
| 일본어 | 4 | 110 | 2 | 105 | +103 |
| 한국어 | 4 | 67 | 63 | 63 | 0 |
| 영어 | 4 | 107 | 100 | 100 | 0 |

중국어·일본어는 공식 사람 화자 구간을 완전한 화자 입력으로 넣어 경계 연결만 격리했다. 중국어 변경 결과는 단일 화자 89자, 실제 겹말로 남긴 문자 10자, 미확인 11자, 오배정 0자였다. 일본어는 단일 화자 105자, 미확인 5자, 오배정 0자였다. 따라서 새 경계가 실제 겹말을 한 사람에게 강제하지 않았다.

## 구현과 한계

`review_speakers`는 다음 위치를 단어 경계로 인정한다.

- 원래 자막의 공백 경계
- 한자·히라가나·가타카나·한글의 내부와 이 문자에 맞닿는 위치

라틴 문자나 숫자로 이어진 한 단어 내부는 계속 경계가 아니다. 하이픈·소수점도 라틴/숫자 단어를 자동으로 나누지 않는다. 공백 포함 `someone speaks` 안의 `one` 거부, `well-known`, `3.14`, 라틴 조각과 한글이 맞닿은 음성 오인, 공백 없는 비CJK 문자의 기존 순차 정렬을 회귀 검사로 고정했다.

반복 글자는 한 토큰씩 앞에서부터 고르지 않는다. 전체 정렬 토큰열에서 원래 글자 순서를 유지하면서 가장 많은 문자를 설명하는 모든 경로를 비교하고, 모든 최적 경로가 같은 위치를 가리키는 토큰만 사용한다. `사과 와사`에서 마지막 `사`의 음성 시각만 있는 경우처럼 위치가 둘 이상이면 미확인으로 남긴다.

반복 탐색 비용을 줄이기 위해 경계에 맞는 후보 위치를 서로 다른 토큰마다 한 번만 계산하고, 각 정렬 상태에서는 이진 탐색으로 남은 후보를 찾는다. 200자 반복 CJK 대역은 `/tmp/r4-main-integration-env`의 Python 3.12에서 34.6ms였다. `대본문자수 × 정렬토큰수`가 40,000을 넘으면 동적 정렬을 실행하지 않고 해당 자막 전체를 검수 대상으로 남긴다. 긴 영상 전체 응답·디코딩 비용 문제까지 해결한 수치는 아니다.

이 결과는 정렬기가 이미 찾은 문자를 버리지 않게 만든 개선이다. 실제 화자 모델의 DER, 자동 전사의 CER, 한국어 완전 발화 분모는 바꾸지 않는다. 따라서 네 언어 전체 정확도 개선으로 합산하지 않으며, 운영 화자 모델 교체 근거도 아니다.

기본 의존성 전체 Python은 **646통과/20skip**, Ruff 검사와 형식 검사는 통과했다. 선택 의존성과 워커 이미지·스택 검사는 새 HEAD의 CI에서 확인한다.
