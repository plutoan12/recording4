# 한국어 음성활동 기준 자료 완전성 감사

FireRedVAD 후보를 한국어까지 같은 기준으로 비교하기 전에, 공개 주석이 120초 평가 구간의 모든 실제 발화를 포함하는지 확인했다. 원음·전사·자동 인식 단어는 비공개 평가 폴더에만 두고 이 보고서에는 집계와 해시만 남긴다.

## KMSAV 표본

[ETRI KMSAV](https://github.com/etri/kmsav)의 ASD 주석과 공개 원본에서 서로 다른 한국어 실제 대화 120초 표본 두 개를 만들었다.

- 첫 표본은 14개 주석의 발화 합집합이 **119.946초**였다. 문장 단위 주석 범위가 거의 전체 구간을 덮어 무음 구간의 false alarm을 측정할 수 없다.
- 두 번째 표본은 24개 주석의 합집합이 **59.970초**였다. 이 표본의 PCM16 16kHz mono SHA-256은 `b3c9babb3133d68d5e052480d8a7249ed203d4aeb6203b0afb7777ca68800e0c`, 주석 파일 SHA-256은 `639f90e2de26921068f6d8cce5ffdd37fb2e30d474bfd2aca0ce3d03ef2287de`다.

두 번째 표본을 정답에 넣지 않은 `faster-whisper small`로 별도 감사했다. 전체 223단어 중 **87단어·253자**가 KMSAV 주석 구간 밖에 완전히 놓였다. 해당 구간을 직접 확인하면 끊기지 않은 정상 한국어 대화가 이어진다. 자동 전사는 사람 정답이 아니지만, 주석 밖 실제 발화가 존재한다는 반례로 충분하다. 따라서 이 ASD 주석의 빈 구간을 무음 정답으로 취급할 수 없다.

이 불완전한 주석으로 잠정 계산한 FireRed와 Silero의 false alarm·precision 값은 폐기했다. 공개 `results.json`이나 네 언어 개선 주장에 포함하지 않는다.

## 다른 공개 샘플 확인

[Nexdata 한국어 대화 샘플](https://github.com/Nexdata-AI/500-Hours-Korean-Conversational-Speech-Data-by-Mobile-Phone) commit `a57e4adbaa43d6418b388f716106332e9562c349`의 WAV/TXT 5쌍을 비공개 폴더에서 확인했다. 파일은 16kHz mono PCM16이며 길이는 **1.449, 3.556, 6.891, 4.480, 6.611초**다. 각 파일에는 한 문장 전사만 있고, 전체 대화 시간축·무음 범위·겹말 시각은 없다. 저장소가 밝힌 이용 조건도 commercial license다. 이 샘플은 ASR 예시로는 쓸 수 있지만 완전 음성 존재나 화자분리 정답은 아니다.

## 코드 방어와 다음 조건

`score_speech_activity.py`의 정답 형식을 객체로 고정했다. 다음 항목이 모두 없으면 점수를 만들지 않는다.

- `schema: 1`
- 평가 음원과 같은 `source_sha256`
- 정확히 `[0, evaluation_end]`인 `annotated_interval`
- 비어 있지 않은 `provenance`
- 사람이 전체 발화를 확인했다는 `speech_presence_complete: true`
- 실제 `turns` 배열

이 선언은 자료의 진위를 자동 보증하지 않지만, 일부 자막 주석을 실수로 전체 무음·발화 정답처럼 채점하는 경로를 차단한다. 출력은 schema 2로 올리고 완전성 선언·주석 구간·출처를 함께 보존해 과거의 느슨한 schema 1 점수와 구분한다. 한국어 수치를 채우려면 완전한 공식 RTTM/UEM이 있는 실제 대화를 확보하거나, 고정한 새 실제 대화의 전체 구간을 두 사람이 독립 주석하고 불일치를 검수해야 한다. 그 전에는 한국어 비회귀와 네 언어 전체 정확도 개선을 입증하지 않는다.

관련 단위 검사는 **23통과**, 기본 의존성 전체 Python은 **635통과/20skip**, Ruff 검사와 형식 검사는 통과했다. 모델·운영 설정·유료 호출·게시에는 변화가 없다.
