# 문체 화면 확인 및 다국어 싱크 후속 검증

## 실제 브라우저

Mac 잠금 해제 후 Chrome의 격리된 SQLite 테스트 앱에서 확인했습니다. 운영 작업은 수정하지 않았습니다.

- 문체 혼용 안내에 `합니다체: 자막 1번`, `비격식·서술체: 자막 2번` 표시.
- 번역 불러오기 후 `녹화 준비가 끝났습니다.`, `아직 진행 중이었다.`가 원래 시각과 함께 그대로 표시.
- 자막 전용 수정 버튼은 `수정 자막으로 새 버전 제작`으로 표시.
- 접근성 트리와 실제 스크린샷으로 안내와 입력칸이 잘리지 않는 것을 확인. 영상은 없는 테스트 작업이므로 영상 재생 검증은 포함하지 않습니다.

## 표본과 판정

영어·일본어·중국어는 [Google FLEURS](https://huggingface.co/datasets/google/fleurs)의 CC-BY-4.0 사람 낭독 음성을 언어별 3개 사용했습니다. 고정 리비전의 validation(dev) 아카이브에서 처음 등장하는 유효 파일 3개를 읽었습니다. 파일명·해시·리비전은 `*-source.json`에 있습니다. 본문과 음성 파일은 커밋하지 않습니다.

`fetch_fleurs_speech.py`는 전체 아카이브를 저장하지 않고 필요한 표본만 읽으며, 요청 개수가 부족하면 실패합니다. 데이터 서버의 test 파일 크기 제한 및 validation 조회 실패를 피하기 위해 공식 원본 아카이브를 사용합니다.

이전 한국어 표본 9개와 동일한 10조건(짧은 영상, 반복 긴 영상, 짧은/긴 간격, 빠른/느린 말, 작은 음량, 잡음 2종, 음악 도입), 이동 0/+2.5초를 검사했습니다. 한국어 현재 결과는 앞선 [동일 코드 검사](../style-sync-matrix-2026-09-19/after.json)를 참조합니다. 새로 실행한 기본 설정 검사는 나머지 3언어 60개입니다.

**소수의 사람 낭독 표본을 반복·변형한 통제 실험입니다.** 자연 촬영 영상, 겹치는 대화, 각 언어 전체의 성능을 대표하지 않습니다. 기준 발화 경계는 깨끗한 입력의 음량 기반 추정이며 수동으로 검증한 음소 경계가 아닙니다. 여기서 측정한 것은 번역 품질이나 문장별 강제 정렬이 아니라 전체 자막의 일정 시간 이동 복구입니다.

통과 기준은 시작·끝 및 이동값 최대 오차 0.5초 이하, 글자/개수 보존입니다. 거부는 실패로 셉니다.

## 현재 운영 코드 결과

| 표본 | 통과/전체 | 관측 결과 |
|---|---:|---|
| 한국어(이전 동일 코드 측정) | 20/20 | 최대 0.50초 |
| 영어 | 0/20 | 18개 거부, 나머지 2개 오차 0.65초 |
| 일본어 | 0/20 | 오차 1.01~4.35초, 보정기는 성공으로 반환 |
| 중국어 | 20/20 | 최대 0.05초 |

원시 결과는 `en-current.json`, `ja-current.json`, `zh-current.json`입니다. **네 언어 싱크 검증 완료/전체 통과라고 해석하면 안 됩니다.** 특히 일본어 표본의 큰 오차가 운영의 상한 검사(10초)만으로 차단되지 않았습니다. 결과 검수는 필수입니다.

영어 표본 중 두 파일의 최대 음량은 약 -32.5/-38.4dB로 작았습니다. 기본 WebRTC 감지기의 전체 발화 감지량이 적었으며 auditok로 짧은 조건을 비교해도 거부했습니다. 저음량이 원인 후보지만 독립적인 수동 경계/정규화 비교 없이 유일한 원인으로 단정하지 않습니다.

## 개선 후보를 운영에 넣지 않은 이유

긴 자막의 10초 제한을 실제 최대 자막 길이로 늘리는 후보를 별도로 실험했습니다. 일본어는 18/20으로 개선됐지만 한국어 10/20, 중국어 15/20으로 악화됐습니다. 중국어 한 조건은 6.64초 오류가 났습니다. 영어는 20개 모두 거부했습니다.

- `*-rejected-candidate.json`: 같은 기준으로 다시 실행한 4언어 80개 결과.
- `rejected-duration-cap.patch`: 재현/검토를 위한 **미적용 후보**. 운영에 적용하지 마세요.
- 후보는 Python 회귀 테스트를 통과했지만 실제 음성 품질의 회귀를 발견했으므로 폐기했습니다. 코드와 이미지 태그를 기존 버전으로 복구했고, 실행 중인 서비스에는 후보를 배포하지 않았습니다.

자막 길이와 실제 발화 마스크가 다르므로 제한 하나를 바꾸는 것만으로 안정적으로 해결되지 않습니다. 다음 개선은 사람이 확인한 기준 경계를 확보한 뒤 음량 보정·발화 검출기 비교와 보정 신뢰도 판정을 함께 평가해야 합니다. 언어별로 유리한 결과만 선택하거나 허용 오차를 늘려 통과시키지 않습니다.

## 재현

워커의 Python·FFmpeg 환경에서 실행합니다. scripts를 PYTHONPATH에 두면 공통 helper를 가져올 수 있습니다. 다운로드 출력 경로는 새 디렉터리여야 합니다.

```sh
python scripts/fetch_fleurs_speech.py --language en --count 3 --out /tmp/fleurs-en
python scripts/verify_sync_matrix.py --directory /tmp/fleurs-en --out /tmp/results-en --limit 0.5
# ja, zh도 같은 명령. 실패 조건이 있으면 종료 코드 1이 정상적인 검사 결과입니다.
```

유료 번역·더빙 호출과 YouTube 업로드는 하지 않았습니다. 최종 운영 기능 코드는 이전과 동일하고 새 다운로드 도구 및 측정 기록만 추가했습니다.

최종 Python 회귀 검사 399 통과·5 조건부 skip, Ruff 통과. 실행 중인 워커 및 복구한 워커 이미지의 싱크 소스 해시가 저장소와 일치하며 운영 상태 검사 healthy를 확인했습니다.
