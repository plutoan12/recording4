# 원문 정렬로 싱크 성공을 검증하는 경로

## 적용한 동작

보정기가 성공을 반환해도 시간 근거가 없으면 새 대본을 저장하지 않습니다. 이 검증은 기본/작은 음량/긴 문장 세 모드 모두에 적용합니다.

- 먼저 기존 발화 보정값을 원음 경계와 대조합니다. 분산된 경계 근거가 3개 이상이고 이동량 차이가 0.5초 이내이면 채택합니다.
- 근거가 부족하면 기존 `align_text`를 엄격 모드로 실행합니다. 지정한 **원문 음성 언어**와 원문 대사만 사용합니다. 단어 대응이 다르거나 영 길이 단어 비율이 10%를 넘는 정렬은 사용할 수 없습니다. 번역문으로 원본 음성을 정렬하지 않습니다.
- 원문 정렬과 발화 보정이 0.5초 안에서 일치하면 기존 일정 이동값을 유지합니다. 충돌하면 평균으로 타협하지 않고 거부합니다.
- 필요하면 임시 사본을 FFmpeg `highpass=f=100,afftdn=nr=12:tn=1,dynaudnorm=f=150:g=15:p=0.9:m=100`으로 처리해 다시 정렬합니다. 원음 파일·최종 영상 소리는 바꾸지 않습니다. 두 정렬 결과가 충돌하면 거부하며, 유효한 정렬이 하나뿐이고 발화 보정도 없으면 원음 경계의 별도 확인이 필요합니다.

대사 정렬은 자막 전체를 정확히 대응시켜야 하며, 3개 이상·60% 이상 자막의 중심 이동량이 일치하고 전체 구간의 절반 이상에 분포해야 합니다. 단어가 이동된 자막 시간 밖으로 벗어나는지도 확인합니다. 자막에는 발화 앞뒤 여유 시간이 있으므로 단어 경계를 자막 경계로 덮어쓰지 않습니다. 원문 문구·각 자막 길이를 유지하고 일정 이동만 적용합니다. 프레임률 변경은 이 검증 경로에서 거부합니다.

## 원문 → 번역 연결과 저장 안전성

API/UI에 원문 음성 언어 선택을 추가했습니다. 영어 음성이면 영어 원문 대본을 먼저 보정하고, 새 번역 작업이 그 시각을 한국어 등 목표 자막으로 복사합니다. 기존 번역 결과와 이미 승인된 영상은 수정하지 않습니다. 원문 대본으로 등록한 텍스트가 실제로 원문인지에 대한 의미 판별을 완전히 보장하는 기능은 아닙니다.

요청 시 원문 버전·언어를 작업 설정에 고정합니다. 이전 API가 만든 작업도 실행 시작 때 버전을 고정합니다. 검사 중 새 대본이 저장되면 오래된 결과는 저장하지 않습니다. 안전한 고정 오류 안내만 관리화면에 표시하며, 모델 로그·대본을 오류에 노출하지 않습니다.

## 동일한 140조건 결과

[이전 검사](../sync-boundaries-2026-09-19/REPORT.md)의 같은 공개 사람 낭독 원본과 10개 통제 조건, 같은 이동량을 사용했습니다. 기존 80개는 0/+2.5초, 추가 60개는 -0.73/+1.37/+4.12초입니다. 시작·끝·이동량 오차 **0.5초 이하**, 문구/개수 보존 조건을 유지합니다. 거부도 실패입니다.

| 표본 | 이전 통과 | 이번 통과 | 이번 거부 | 기준 초과인데 성공 처리 |
|---|---:|---:|---:|---:|
| 기존 영어 quiet | 20/20 | 18/20 | 2 | 0 |
| 기존 일본어 long_cues | 20/20 | 20/20 | 0 | 0 |
| 기존 한국어 standard | 20/20 | 10/20 | 10 | 0 |
| 기존 중국어 standard | 20/20 | 16/20 | 4 | 0 |
| 추가 영어 quiet | 18/30 | 21/30 | 9 | 0 |
| 추가 일본어 long_cues | 30/30 | 27/30 | 3 | 0 |
| 합계 | 128/140 | **112/140** | **28** | **0** |

- 3.94초 틀린 값을 성공으로 반환하던 추가 영어 음악 3개는 모두 거부합니다.
- 추가 영어 느린 말 3개는 정렬 재시도로 복구됐습니다.
- **이전에 통과했던 19개도 이제 거부됩니다.** 영어 짧은 표본 2개, 한국어 10개, 중국어 4개는 정렬 근거가 부족하고, 추가 일본어 짧은 표본 3개는 발화 보정과 원문 정렬이 충돌합니다. 성공 처리의 보수성을 높인 대가이며, 전체 정확도 개선/140개 해결로 표현하면 안 됩니다.
- 새로 거부하는 경우에도 원래 자막 시각은 유지합니다. 원래 맞던 자막에 잘못된 이동을 강제로 적용하지 않습니다.

상세 수치는 언어별 JSON, 이전 결과와의 변화는 `comparison.json`에 있습니다. 모델 추론은 같은 오디오 해시·원문·언어·모델·설정에 대해 시간 이동 시험 사이에서만 재사용했습니다(검증 도구에서만 사용, 제품의 영구 캐시가 아님). 정답 시각이나 테스트 이동량은 모델 추론 캐시의 입력이 아닙니다. [추론 기록](inference.json).

이 표본은 반복·속도 변경·합성 잡음/음악으로 만든 통제 영상입니다. 기준 경계는 음량으로 추정했으며 수동 음소 정답이 아닙니다. 추가 표본도 이번 개발 과정에 사용했으므로 미사용 독립 평가라고 부르지 않습니다. 이번 140개에서 기준 초과 성공은 없지만 다른 영상의 오판이 없다는 보장은 아닙니다. 특히 짧은 대본, 잔향·잡음, 비대칭 자막 여유 시간, 부분 편집/시간 늘어남, 가져온 번역 대본은 여전히 한계입니다.

## 검증과 재현

- Python **445 통과, 5 조건부 skip**, Ruff·TypeScript·Vite 빌드 통과.
- 충돌 시 거부, 원문 언어 전달, 원음/문구/길이 유지, 사본 정리, 원문 버전 고정과 검사 중 수정 충돌, 번역문이 보정한 원문 시각을 사용하는 경로를 검사했습니다.
- Mac 잠금으로 실제 브라우저 화면 확인은 하지 못했습니다. 언어 선택 UI는 타입 검사와 빌드로 확인했습니다.
- 유료 API·더빙·YouTube 업로드/게시 없음. 새 모델이나 서비스 가입 없음.

```sh
python scripts/verify_sync_matrix.py --directory /tmp/en --out /tmp/en-check --profile quiet --language en
python scripts/fetch_fleurs_speech.py --language en --skip 3 --count 6 --out /tmp/en-new
python scripts/verify_sync_matrix.py --directory /tmp/en-new --out /tmp/en-new-check --profile quiet --language en --offsets -0.73 1.37 4.12
```

일본어는 ja/long_cues, 한국어·중국어는 ko·zh/standard를 사용합니다. 기존 자료의 출처·해시는 이전 보고서에 있습니다. 실패가 있으면 종료 코드 1입니다. 거부를 성공으로 바꾸거나 기준을 완화하지 않았습니다. 원본 영상·음성·대본·인증정보는 GitHub에 저장하지 않습니다.

실제 무음·일정한 톤·잡음을 각 세 모드에 넣어 **9/9 거부**를 확인했습니다. 분석 사본과 동일하게 디코딩한 원음의 샘플 수는 **1,263,616 프레임으로 같고** 원본 영상 SHA도 유지됐습니다. [검사 기록](safety.json). 모델이 근거 부족으로 중단할 때 상위 라이브러리의 FFmpeg 파이프 종료 경고가 나올 수 있었으며, 이를 성공 결과로 사용하지 않았습니다.

## Mac 서버 반영

API·워커·디스패처·모니터·웹을 다시 빌드하고 재시작해 전체 서비스 healthy를 확인했습니다. 배포된 API의 원문 언어 선택 계약과 워커 소스 해시가 저장소와 일치합니다. 배포 워커에서 캐시 없이 음악 오판 3건 거부, 느린 영어 3건 복구, 일본어 짧은 음성 2건 통과를 재검증했습니다(총 8건 예상 동작, 거부 3건 포함). 원본 세 영상의 SHA는 그대로입니다. [배포 검사 기록](rollout.json). 브라우저 실화면 검증은 여전히 미완료입니다.
