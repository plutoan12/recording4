# 저음량·긴 자막의 남은 싱크 실패 수정

## 변경과 판정 범위

PR #28에서 남은 기존 영어 8개·일본어 2개 실패를 수정했습니다. 언어 이름이나 정답 이동량으로 분기하지 않습니다. 사용자가 선택하는 `quiet`, `long_cues`의 일정 이동 보정에만 추가 분석을 적용하며 `standard`와 프레임률 변경 모드는 유지합니다.

1. ffsubsync의 발화 기반 이동값 주변에서 원음의 에너지 경계를 비교합니다. 자막 양끝이 각각 1.5초 안에 있는 구간만 후보입니다. 고역 통과 후 100Hz 에너지·지역 최대값·잡음 바닥을 사용하며 이 값은 음성 인식 결과가 아닙니다.
2. 서로 다른 자막/오디오 구간 3개 이상이 같은 이동량을 지지해야 합니다. 중심 ±0.25초 합의, 자막 전체 범위의 절반 이상에 분포, 기존 이동값에서 최대 1초 이내를 요구합니다. 중복·겹친 자막으로 지지 수를 늘리거나 동수의 다른 답이 있는 경우는 채택하지 않습니다. 원문/길이는 바꾸지 않습니다.
3. 기존 정렬이 실패하거나 음수 시각·탐색 한계에 걸리면 분석 사본만 강하게 정규화해 한 번 더 계산합니다. 이 재시도는 발화 감지 성공에 더해 **원음 경계의 합의까지 있어야** 채택합니다. 근거 부족은 기존 대본을 유지하는 실패입니다.
4. 일정한 잡음/음량은 경계 근거가 부족하므로 새 방식에서 거부합니다. 1초 평균 에너지 최대가 잡음 바닥의 2배 미만인 경우입니다. 무음·상수 발화 마스크 방어는 기존대로 유지합니다.

강한 증폭을 모든 입력에 적용하거나 허용 오차를 늘리지 않았습니다. `boundary_support`, `recovery_used`를 작업 결과에 남깁니다. 분석 파일은 임시 디렉터리에서 지우고, 오디오는 청크 단위로 축약해 읽습니다. 경계 후보와 합의 구간 검색은 정렬된 인덱스를 사용해 긴 자막의 제곱 크기 메모리 사용을 피합니다. SciPy 1.17.1은 이미 워커에 있던 의존성을 직접 고정한 것입니다.

## 기존 회귀 표본

출처·구성은 [이전 보고서](../sync-profiles-2026-09-19/REPORT.md)와 같습니다. 10개 통제 조건 × 이동 0/+2.5초, 시작·끝·이동량 오차 모두 **0.5초 이하**, 텍스트/개수 불변. 거부는 실패로 셉니다.

| 표본과 선택 모드 | 이전 | 수정 후 | 수정 후 최대 오차 |
|---|---:|---:|---:|
| 영어 quiet | 12/20 | 20/20 | 0.43초 |
| 일본어 long_cues | 18/20 | 20/20 | 0.10초 |
| 한국어 standard | 20/20 | 20/20 | 0.50초 |
| 중국어 standard | 20/20 | 20/20 | 0.05초 |

`*-final.json`에 수치를 저장합니다. 소수의 사람 낭독을 반복·속도 변경·잡음/화음 합성한 영상입니다. 사람이 확인한 발화 경계나 자연 현장 영상 전체에 대한 품질 보장은 아닙니다.

## 겹치지 않는 추가 표본

같은 [FLEURS](https://huggingface.co/datasets/google/fleurs)의 고정 리비전에서 기존 앞 3개를 제외한 다음 6개씩을 en/ja에 사용했습니다. 새 이동량 -0.73/+1.37/+4.12초와 같은 10조건, 언어별 30검사입니다. 출처·파일 해시는 `*-holdout-source.json`, 이전 코드는 `*-holdout-before.json`, 수정 코드는 `*-holdout-final.json`입니다.

| 추가 표본 | 이전 PR #28 | 수정 후 |
|---|---:|---:|
| 영어 quiet | 3/30 | 18/30 |
| 일본어 long_cues | 29/30 | 30/30 |

추가 표본의 첫 평가 후 탐색 한계값을 성공으로 받는 문제를 막고 재검사했습니다. 따라서 최종 수치를 완전히 손대지 않은 독립 평가라고 부르지 않습니다. 기존에 통과한 추가 사례가 실패로 바뀐 경우는 없습니다.

**새 영어 표본의 12개 실패가 남아 있습니다.** 느린 말·15dB 잡음·5dB 잡음 각 3개는 근거 부족으로 거부합니다. 음악 조건 3개는 기존과 같은 3.94초 오차의 잘못된 보정값을 반환합니다. 시간 경계만으로 모든 대본/배경음의 정답을 판별할 수 없으므로 검수·새 대본 버전·기존 버전 보존이 계속 필요합니다. 문체는 사용자 선택대로 원문 말투를 유지하고 혼용 가능성만 표시합니다.

## 재현

워커 환경에서 아래 스크립트를 실행합니다. 무료 로컬 계산이며 번역·더빙 API나 YouTube 호출이 없습니다.

```sh
python scripts/fetch_fleurs_speech.py --language en --skip 3 --count 6 --out /tmp/en-new
python scripts/verify_sync_matrix.py --directory /tmp/en-new --out /tmp/en-new-check --profile quiet --offsets -0.73 1.37 4.12
```

일본어는 `--language ja`, `--profile long_cues`를 사용합니다. 실패가 있으면 종료 코드 1입니다. 원본 영상·음성·대본·인증정보는 커밋하지 않고 검사 수치와 공개 데이터 출처만 저장했습니다.

## 코드 검증

- Python **433 통과, 5 조건부 skip**, Ruff·diff 공백 검사 통과. 선택 의존성이 없는 기본 CI에서는 해당 통합 검사만 skip합니다.
- 이동량 -0.73/0/1.37/4.12의 경계 합의 불변성, 중복·충돌·편중된 근거 거부, 재시도 근거 필수, 기본 모드 보존, 탐색 한계 방어 검사.
- 5,000개 자막 합의 검사 및 인덱스 최적화 전후 실제 40음원 × 81후보 = **3,240개 결과 동등성** 확인.
- 실제 무음·일정한 톤·정상분포 잡음 WAV를 세 모드로 검사해 **9/9 거부**. [검사 기록](safety.json). 이는 모든 종류의 음악/잡음을 자동 구분한다는 의미가 아닙니다.
- 관리화면/API의 호출 계약은 바꾸지 않았습니다. 이번에는 브라우저 화면을 다시 검증하지 않았습니다.

## Mac 운영 반영

API·워커·디스패처·모니터를 재빌드하고 작업 실행 중이 아님을 확인한 뒤 재시작했습니다. 전체 서비스 healthy, DB·저장소·Redis·워커 점검 통과. 배포 파일 해시가 체크아웃과 일치합니다. 운영 워커에서 이전에 실패한 en/ja 저음량 MP4를 이동 -0.73/0/+2.5/+4.12초로 다시 검사해 **8/8 통과**, 원본 SHA·자막 글자·길이 보존을 확인했습니다. [배포 검사](rollout.json). 실제 사용자 작업·게시·유료 처리를 새로 만들지 않았습니다.
