## 완료한 작업

- README를 문서 진입점으로 구성.
- 목표·가정·MVP·확인할 사항 분리.
- 구성도, 처리 단계, 데이터 모델, 승인 버전, 실패 복구 설계 작성.
- 기술 선택 이유 및 공식 참고 문서 정리.
- 단계별 체크리스트와 완료 기준 작성.
- AGENTS.md와 CLAUDE.md로 공통 협업 절차 연결.
- 설계 검토 수행 및 ARCHITECTURE.md 수정 3건 반영. 이유는 TECH_DECISIONS.md 변경 기록에 남김.
  - 배경음 합성 문장이 원음 전체 혼합과 대사 중복 방지를 동시에 주장하던 모순 정정.
  - `segments`를 `transcript_segments`(원본 소속)와 `translated_segments`(작업 소속)로 분리해 STT 재사용 전제를 데이터 모델에 반영.
  - 제작·게시 상태에 rejected/failed/cancelled 추가 및 전이표 명시.

## 남은 설계 문제

이번 검토에서 확인했으나 수정하지 않은 항목입니다. 대부분 사용자 결정이나 샘플 측정이 필요합니다.

| 번호 | 문제 | 영향 | 필요한 것 |
|---|---|---|---|
| R1 | 더빙 길이 정합 정책 부재. ARCHITECTURE.md 처리 5단계가 "허용 범위"만 언급 | 구간 겹침, 자막 오차, 재생성 비용 | 허용 오차 수치, 조정 수단 우선순위(무음 흡수 → 속도 조절 → 번역 축약), 속도 조절 상한, 상한 초과 구간 처리 방침 |
| R2 | 게시 후 수정 경로 없음. YouTube는 업로드된 영상의 파일을 교체할 수 없음 | 공개·예약 후 결함 발견 시 복구 절차 없음 | 새 영상 업로드 + 기존 영상 비공개 전환 + publications 연결 갱신 흐름 정의 |
| R3 | `stage_runs.입력 해시` 구성 요소 미정 | 모델·음성·설정을 바꿔도 과거 산출물이 재사용될 수 있음 | 해시에 공급자·모델·음성·프롬프트·설정 버전 포함 여부와 `jobs.설정 버전`과의 관계 정의 |
| R4 | 장시간 단계를 Celery 태스크 하나로 실행할지 미정 | Redis 재전달과 워커 재시작 시 중복 실행·유실 | 제출/폴링/수거를 짧은 태스크로 분리하고 진행 상태는 DB가 보유하는 규칙 명시 |
| R5 | 비용 상한을 강제할 지점 없음. 데이터 모델에 예산·한도 엔터티 없음 | 재시도 루프가 유료 API를 반복 호출할 위험 | 호출 전 비용 추정과 차단 지점, 재시도 한도와 비용 상한의 연결 |
| R6 | 용어집과 화자→음성 매핑 엔터티 누락 | 번역 용어 일관성, 다중 화자 더빙 | 두 엔터티의 소속과 버전 관리 방식 정의 |
| R7 | 미리보기 서명 URL 발급 주체가 구성도에서 불명확 | 인증된 관리자만 접근한다는 원칙과 어긋나 보임 | 업로드 경로처럼 API가 발급하도록 구성도·본문에 명시 |
| R8 | YouTube Data API 일일 쿼터가 처리량 가정에 없음 | 하루 업로드 가능 편수 제한 가능성 | 공식 문서로 쿼터와 상향 신청 필요 여부 확인. 이번 검토에서 수치는 확인하지 않음 |
| R9 | 테스트 전략 없음. `tests/` 디렉터리만 계획됨 | 3단계 완료 기준이 사실상 육안 검사 | 외부 API 모킹, 상태 전이 테스트, 중복 실행 재현 방법 정의 |
| R10 | 삭제 요청 시 파생물 연쇄 삭제 정책 없음 | 대본에 개인정보가 포함될 수 있음 | 원본 삭제 시 STT·번역·음성·결과물 처리 방침을 보관 기간 정책과 함께 결정 |

구현 일정과 관련해 IMPLEMENTATION_PLAN.md 1단계(샘플 측정)와 2단계(기반 구축)는 병렬 진행이 가능합니다. 2단계는 언어·모델 확정을 기다릴 필요가 없습니다.

## 검증 범위

이번 변경은 Markdown 문서만 대상으로 합니다. 저장소 내 상대 링크 14개가 모두 존재하는 것과 필수 문서 존재 여부를 확인했고, 수정한 문장·표를 문서 간 참조(IMPLEMENTATION_PLAN 3·4단계, PROJECT_BRIEF 비용 산정)와 대조했습니다. API 연결·영상 품질·배포·실제 업로드 테스트는 수행하지 않았습니다. Mermaid는 소스 구문을 검토했으며 GitHub 화면 렌더링과 새로 추가한 표의 시각 검증은 별도입니다. 남은 설계 문제 표의 R8은 공식 문서로 확인하지 않은 항목입니다.
