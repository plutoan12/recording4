# 자막 표시 방식과 실제 검증

## 자막 두 벌 방지

편집기와 단계별 제작 화면의 **자막 표시**에서 선택합니다.

- **영상에 굽기**: 기존 기본값. 영상에 대사를 표시하며 YouTube 자막 트랙은 올리지 않습니다.
- **YouTube 트랙만**: `burn_subtitles=false`. 영상에는 대사 자막을 굽지 않고 별도 트랙을 올립니다. 화면 제목은 유지합니다. 내려받은 MP4에는 대사 자막이 없으며 SRT/VTT를 함께 사용할 수 있습니다.

선택은 렌더 요청에 저장됩니다. 이미 승인된 영상의 설정을 바꾸지 않고 새 결과물을 만들어 다시 검수합니다. 예전 결과물은 구운 자막으로 간주합니다. 숏폼의 자막 언어와 원어 유지 작업의 원본 언어를 정확하게 지정하세요.

트랙 전용 게시에는 `R4_YOUTUBE_CAPTIONS_ENABLED=true`, `youtube.force-ssl` OAuth 권한, 언어가 있는 자막이 필요합니다. 자막 업로드 실패·언어 누락 시 공개 예약을 중단합니다. 비공개 영상 ID와 업로드 기록은 유지하므로 설정을 고쳐 재개할 때 영상을 중복 업로드하지 않습니다.

## 사람 목소리 싱크 검증에서 발견한 한계

`fetch_korean_speech.py --count 3`로 Bingsu/zeroth-korean 공개 낭독 표본 3개(34.18초)를 받아 기존 `verify_sync.py`에 넣었습니다. 정답 자막을 2.5초 뒤로 민 경우 ffsubsync 기본값은 -23.25초, 속도 비율 0.959를 제안했습니다. 자막 두 개가 음수 시각으로 사라져 **기존 개수 검사에서 실패**했고 잘못된 대본은 저장되지 않았습니다.

시간 늘이기를 끄고 이동을 10초로 제한한 대안도 -3.91초로 실패했습니다. auditok 대안은 -1.76초를 제안해 정답과 0.74초 차이였고, 이미 맞는 자막도 +0.74초 이동시켰습니다. 0.5초 기준을 통과하지 못해 대안 설정은 채택하지 않았습니다. 기존 보호 장치를 유지하며 **사람 목소리 싱크 품질은 통과로 간주하지 않습니다.**

재현: 워커 이미지에서 `scripts/fetch_korean_speech.py --out /audio --count 3` 후 `scripts/verify_sync.py --directory /audio --offset 2.5`. 실패한 보정은 원본 대본을 유지합니다. 잡음·긴 영상 등 광범위 품질 검증은 별도입니다.
