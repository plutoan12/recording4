# 자막·타이포그래피 조사 — 2026-09-20

## 조사 결론과 근거의 범위

recording4의 다음 제작 우선순위는 **세로형 레이아웃 → 단어 시각 데이터 → 단어 강조 → 이중 언어 → 인물 뒤 타이틀**을 제안한다. 이미 만든 15종의 색상 변형보다 실제 발화와 맞는 강조, 모바일에서 읽히는 배치가 더 큰 기능 확장이다.

한국어·영어 검색으로 제작사 기능 설명, 공식 규격, 2026년 디자인 기사와 상품 사례를 확인했다. 조회수 상위 영상의 대표 표본을 수집하거나 효과별 시청 유지율을 측정한 조사는 아니다. 아래 ‘확인’은 기능·사례의 존재를 뜻하며 시장점유율이나 유행 순위를 뜻하지 않는다. 판매사의 정확도·조회수 상승·바이럴 보장 수치는 채택하지 않았다. 오래된 기법이 현재도 제공된다고 해서 2026년에 새로 생긴 기법으로 분류하지 않는다.

## 새 템플릿 제작안 8종

아래 이름과 수치는 자체 설계 초안이며 아직 구현·검증하지 않았다. 공통 기준은 1080×1920 세로형, 폰트 라이선스 동봉, 같은 대사로 비교하는 것이다.

| 제안 ID | 모습과 동작 | 필요한 데이터 | 난이도 |
|---|---|---|---|
| clean-focus | 흰색 두꺼운 글자, 현재 어절만 노랑, 위치 고정 | 어절별 시작·끝 | 중 |
| marker-follow | 현재 어절 뒤에 둥근 형광펜 박스 이동 | 어절 시각·실제 글자 폭 | 중 |
| soft-pop | 문장 고정, 핵심어만 100→106→100% 확대 | 강조 범위·시각 | 중 |
| bilingual-stack | 한국어 상단, 작은 영어 하단, 별도 줄바꿈 | 검수한 번역·문장 대응 | 중 |
| editorial-depth | 인물 뒤 큰 제목, 전면 작은 대사 | 영상·인물 마스크·추적 | 높음 |
| handwritten-note | 대사 아래 손으로 그은 듯한 밑줄 | 강조 구간·벡터 경로 | 중 |
| speaker-chip | 화자 이름표·색상으로 구분, 본문은 고정 | 화자 ID·겹치는 발화 | 중 |
| number-impact | 금액·비율·횟수만 크게 강조 | 숫자 범위·발음 시각 | 중 |

초기 글자 크기·위치 값은 화면비와 실제 문자열 폭으로 조절해야 한다. 영어의 ‘한 줄 몇 단어’ 지침을 한국어에 그대로 적용하지 않는다. 한국어는 어절·조사·의미 단위를 함께 보고, 영어 브랜드명과 숫자+단위를 분리하지 않는 규칙을 제안한다. 플랫폼 UI가 덮는 영역은 버전·기기에 따라 달라질 수 있으므로 하나의 고정 안전영역을 모든 앱의 보장값으로 쓰지 않는다.

## 자막 파일과 템플릿의 역할

| 파일 | 보관할 내용 | 이번 연구에서의 활용 |
|---|---|---|
| SRT | 문장과 구간 시간 | 일반 자막 교환용. 현재 생성기가 내보내는 SRT에는 디자인·단어별 시각이 없다 |
| WebVTT | 큐·스타일 관련 구조·큐 내부 타임스탬프 | 웹 플레이어용 후보. 규격 지원과 현재 변환기의 보존 기능은 별도 검증 필요 [9] |
| ASS | 글꼴·배치·색상·모션·카라오케 태그 | 현재 렌더러의 확장 경로. k는 구간별 전환, kf는 좌→우 채우기; 단위는 1/100초 [10] |
| 내부 JSON 제안 | words, emphasis, speaker, translations, layout | 단어 시각과 디자인을 잃지 않는 기준 데이터. 새 스키마는 아직 구현하지 않음 |
| MOGRT·AEP·Fusion | 편집기 고유 그래픽·프로젝트 | 별도 내보내기 모듈과 앱 검증이 필요. SRT 확장자만 바꿔서 만들 수 없음 |

특히 ‘현재 단어만 강조’와 ‘지나간 단어가 계속 채워진 카라오케’는 다르다. ASS k/kf만 넣으면 원하는 전자와 다를 수 있어, 원래 색으로 돌아오는 구간별 색상 이벤트를 설계해야 한다. SRT 구간을 단어 수로 균등 분할하면 실제 발화 정렬이 아니라 추정값이다. 원음 정렬 또는 사람이 확인한 단어 시각이 없으면 결과에 estimated로 기록하는 것을 제안한다.

## 편집기별 연구 방향

- **Premiere:** 공식 번역·다중 자막 트랙을 활용하고, 모션 그래픽은 별도 출력 경로로 취급. 자막 텍스트를 고친 뒤 모션에도 반영되는지 검증 [3].
- **After Effects:** Text Animator/Selector로 글자·단어·줄을 제어. 기존 JSX 경로에서 한글 폭·폰트·소스 대체를 확인한 뒤 확장 [6].
- **CapCut:** 공식 이중 자막 및 인물 뒤 템플릿을 참고. 현재 recording4에서 CapCut 편집 가능한 네이티브 템플릿 생성은 미구현 [4][5].
- **DaVinci:** Resolve 20 문서상 AI Animated Subtitles는 Studio 기능이며 전사 엔진과 연동. 외부 SRT에도 모든 단어 타이밍이 그대로 생긴다고 가정하지 말고 실제 설치 버전으로 확인 [2]. 이 문서는 Resolve의 최신 버전 번호를 확정하는 자료로 사용하지 않았다.

## 현재 코드와 차이

로컬 코드 확인 결과 motion_templates.py는 15개 프리셋과 1920×1080 ASS/영상 출력을 제공한다. typewriter/cascade는 자막 전체 길이를 기준으로 등장 시점을 계산하며 원음의 단어별 발화를 읽지 않는다. 따라서 다음 우선 작업은 세로형 좌표, 단어 시각 입력, 한국어 줄바꿈이다. 이번 작업은 연구 문서 작성이며 코드를 변경하거나 새 템플릿을 완성한 것은 아니다.

## 후속 검증 계획

1. 자체 대본으로 한국어 대화, 한·영 혼용, 숫자·고유명사, 빠른 발화, 두 화자, 긴 번역문 등 6개 샘플을 준비한다.
2. 같은 영상·음성·대사에 clean-focus/marker-follow/soft-pop/bilingual-stack을 비교한다.
3. 한글 받침·결합문자·이모지, 줄바꿈, 화면 밖 넘침, 단어 강조 타이밍, 수정 후 타이밍 재연결을 점검한다.
4. 실제 휴대전화 표시와 각 편집기 가져오기를 확인한다. 앱 내 검증 전에는 호환 완료라고 표시하지 않는다.
5. 유행 효과를 판정하려면 동일 내용의 비교 실험으로 읽기 오류·선호도를 측정하고, 배포 후 유지율은 채널·길이·주제별로 구분한다. 조회수만으로 디자인의 효과를 단정하지 않는다.

기존 Starter Kit·Mixkit 원본은 연구·개인 작업용 보관 상태를 유지한다. 새 마켓용 결과는 자체 구현과 원본/폰트별 권리 확인이 가능한 자료로 구성하는 방향을 제안한다.
