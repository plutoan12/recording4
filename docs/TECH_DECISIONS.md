# 기술 선택과 결정 기록

## 2026-09-19: ASS 템플릿을 서버와 브라우저에서 공유

기존 pysubs2·FFmpeg 경로에 5개 스타일을 추가하고 JASSUB 2.5.16으로 동일한 ASS 생성기의 예시를 표시합니다. CSS 전용 엔진을 추가하면 최종 렌더와 두 가지 스타일 정의를 유지해야 하므로 이번에는 도입하지 않습니다. 미리보기는 실제 영상 대신 고정 예시이며 결과물 승인을 대체하지 않습니다.

화자·원문을 Cue의 선택 필드로 보존하며 기존 작업의 기본 스타일은 classic입니다. 번역과 자막 전용 번역은 원문을 함께 저장합니다. 숏폼 효과는 신뢰된 ASS 태그로만 넣고 사용자 텍스트의 태그는 이스케이프합니다. Noto 한국어 글꼴을 로컬 제공하고 JASSUB 외부 글꼴 조회를 끕니다. 복합 라이선스·글꼴 출처와 한계는 [자막 템플릿](SUBTITLE_TEMPLATES.md)에 기록합니다.

상태: 아래 선택은 설계 추천안입니다. 사용자 확정이나 실제 성능 검증을 의미하지 않습니다. 공식 문서 확인일: 2026-09-18. 구현 시 모델·지원 언어·요금·제한을 다시 확인합니다.

## 공식 근거와 제약

- [GitHub Actions 실행 제한](https://docs.github.com/en/enterprise-cloud%40latest/actions/reference/limits): GitHub 호스팅 러너는 작업당 6시간 제한이 있습니다. 영상 작업 상태를 Actions 실행에 종속시키지 않습니다.
- [S3 서명 URL](https://docs.aws.amazon.com/AmazonS3/latest/userguide/PresignedUrlUploadObject.html): 브라우저가 AWS 자격증명을 보유하지 않고 직접 업로드할 수 있습니다. 같은 키를 덮어쓸 수 있으므로 고유한 파일 키와 업로드 완료 검증을 사용합니다.
- [S3 분할 업로드](https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpuoverview.html): 큰 원본을 부분 단위로 전송합니다. 미완료 업로드 정리 정책도 설정합니다.
- [Celery 설정](https://docs.celeryq.dev/en/main/userguide/configuration.html): 재전달 가능성을 고려해 같은 작업을 여러 번 실행해도 문제가 없도록 구현합니다. Redis의 visibility timeout은 작업 길이에 맞춰 검토합니다.
- [Google STT V2](https://docs.cloud.google.com/speech-to-text/docs/reference/rest/v2/projects.locations.recognizers): 단어별 시간·화자 설정이 있습니다. 모든 모델·언어가 같은 옵션을 지원한다고 가정하지 않습니다.
- [Cloud Translation](https://docs.cloud.google.com/translate/docs/api-overview): Advanced의 용어집을 활용합니다. 번역 품질과 더빙 길이 적합성은 별도 평가 대상입니다.
- [ElevenLabs 타이밍 응답](https://elevenlabs.io/docs/api-reference/text-to-speech/convert-with-timestamps): 음성과 문자 타이밍을 받아 문장 타이밍·자막으로 변환합니다. 원본 구간 길이에 자동으로 맞춰진다는 의미는 아닙니다.
- [Sync 문서](https://sync.so/docs/introduction): 립싱크 후보입니다. 다중 화자, 얼굴 가림, 빠른 장면 전환 등 대표 입력으로 적용 가능성을 확인합니다.
- [YouTube 영상 리소스](https://developers.google.com/youtube/v3/docs/videos): 예약 공개는 비공개이고 아직 공개된 적 없는 영상에 설정합니다. 2020-07-28 이후 생성된 미검증 API 프로젝트의 업로드는 비공개로 제한되며 제한 해제에 감사가 필요할 수 있습니다. 계정 준비 단계에서 확인합니다.
- [YouTube 이어 올리기](https://developers.google.com/youtube/v3/guides/using_resumable_upload_protocol): 세션 URL과 전송 상태를 보존해 중단 후 재개합니다. 성공 응답을 잃었을 때도 기존 세션부터 확인합니다.
- [YouTube 쿼터 계산기](https://developers.google.com/youtube/v3/determine_quota_cost), [쿼터와 감사](https://developers.google.com/youtube/v3/guides/quota_and_compliance_audits): 업로드는 비용이 큰 호출이며 업로드·검색을 별도 쿼터로 분리하는 변경이 안내되어 있습니다. 하루 업로드 가능 편수가 처리량 상한이 될 수 있습니다. **2026-09-18 검토 시점에 이 두 페이지는 작업 환경의 네트워크 정책으로 직접 열지 못했습니다. 수치를 이 문서에 옮기지 않았으므로 계정 준비 단계에서 현재 쿼터와 상향 신청 절차를 직접 확인합니다.**
- [YouTube 영상 수정](https://developers.google.com/youtube/v3/docs/videos/update): 제목·설명·공개 상태는 수정할 수 있습니다. 업로드된 영상의 파일 교체는 지원되지 않는 것으로 보고 설계했습니다. 계정 준비 단계에서 수정 가능한 범위를 확인합니다.

## 구현에서 확정한 사항

2단계 구현에서 실제로 선택한 것만 적습니다. 나머지는 여전히 제안입니다.

| 영역 | 확정 | 이유 |
|---|---|---|
| 상태 컬럼 | `Enum(native_enum=False)`로 저장하고 열거형으로 읽기 | 문자열로 읽히면 전이표 조회가 타입 오류로 깨집니다. 테스트에서 실제로 발견했습니다 |
| 비밀번호 해시 | 표준 라이브러리 `hashlib.scrypt` | 의존성을 늘리지 않고 솔트·작업 계수를 함께 저장합니다 |
| 접근 토큰 | PyJWT HS256 | 관리자 1명 가정에서 세션 저장소가 필요 없습니다 |
| 개발용 저장소 | MinIO (S3 호환) | S3 API를 그대로 쓰면서 계정 개설과 과금이 없습니다 |
| 테스트 DB | 기본 SQLite, 행 잠금 테스트는 PostgreSQL | 대부분은 빠르게 돌리고 동시 예약은 실제 잠금이 필요합니다 |
| outbox 전달 | 별도 디스패처 프로세스의 주기 실행 | 큐 전송 실패가 요청 유실로 이어지지 않습니다 |

## 2026-09-18 구현 결정

사용자의 GitHub 코드 통합 요청으로 로컬 STT(faster-whisper)와 장면 감지(PySceneDetect), 자막(pysubs2), FFmpeg 렌더를 우선 연결했습니다. 기존 Google STT 추천안에 로컬 실행 경로를 추가한 결정이며 유료 STT 성능 비교 결과는 아닙니다. 유료 번역·TTS·립싱크·YouTube는 어댑터로 분리했습니다. 영속적인 무료 분석·렌더 작업에는 별도 media_tasks 테이블을 사용하고 기존 유료 단계/예산 모델은 보존했습니다. 출처·라이선스·미구현 범위는 [오픈소스 통합](OPEN_SOURCE_INTEGRATIONS.md)에 기록합니다.


## 단계별 연결 구현 (2026-09-18)

- 별도 오케스트레이션 서비스를 추가하지 않고 기존 PostgreSQL outbox+Celery를 사용한다. 메시지 하나당 한 단계를 실행하고 결과·후속 요청을 함께 저장한다.
- 번역과 TTS는 공급자 제한에 맞춰 배치/문장별 체크포인트를 저장한다. 립싱크는 원격 ID, YouTube는 업로드 세션과 영상 ID를 재사용한다.
- 공급자 응답 유실은 무조건 재시도하지 않고 정산 확인으로 전환한다. 비용은 실제 청구액이 아닌 설정된 보수적 상한으로 기록한다. 작업·월 예산을 함께 예약한다.
- 더빙은 FFmpeg로 타임라인에 배치하며 현재 원래 배경음도 제거된다. 다음 문장 시작 전 여유 구간과 최대 1.15배 속도 조정만 허용한다. 더 긴 문장은 새 번역 버전으로 수정한다.
- 구체적인 실행 설정·복구·검증 한계는 [단계별 연결](CONNECTED_WORKFLOW.md)에 기록한다.


## Claude 리뷰 반영 (2026-09-18)

- DB 날짜는 SQLite의 naive 값을 UTC로 해석하고, PostgreSQL aware 값은 오프셋을 보존하여 UTC로 변환한다. 예약·실행 점유 검사에 공통 헬퍼를 사용한다.
- 공급자가 확정한 립싱크 종료 실패는 폴링 장애와 분리한다. 종료 실패는 정산 확인 후 새 시도, 폴링 장애는 기존 ID 재조회로 처리한다.
- 수정 번역의 변경되지 않은 음성은 명시적 부모 작업 선택으로 재사용한다. 모델/음성 버전을 모르는 공급자의 자동 전역 캐시는 금지하고, 명시된 버전이 있을 때만 자동 캐시를 허용한다. 문장별 입력 해시에는 모델·음성·언어·출력 계약을 포함한다.
- 실제 청구 비용은 아직 수집하지 않으므로 null로 기록하고 상한 장부와 구분한다. 오래된 미확인 예약은 알림·정산 대상으로 유지하며 자동 해제하지 않는다.


## 2026-09-18: YouTube 링크 원본 가져오기

공개 단일 영상 URL을 정규화해 yt-dlp 전용 워커에 전달한다. 범용 URL 다운로더 대신 YouTube 호스트와 영상 ID만 허용해 임의 내부 주소 입력을 차단한다. 큐/outbox와 기존 SourceAsset 상태를 재사용하며 API 프로세스에서 파일을 다운로드하지 않는다. 워커의 별도 프로세스에 환경 비밀을 전달하지 않고 파일 크기 OS 상한과 실행 제한을 적용한다. 임의 추출기·재생목록·로그인 쿠키를 사용하지 않으며 실패 시 수동 파일 등록으로 대체한다.


## 자막 표시 규칙의 기준 (2026-09-18)

- 자막 길이 단위를 글자 개수에서 **글자 폭**으로 바꾼다. 한글·한자·가나는 1자, 라틴 문자·숫자·공백·문장부호는 0.5자다. Netflix 한국어 자막 지침의 계산 방식이며 `unicodedata.east_asian_width`로 판정한다.
- 기본값을 그 지침(성인물)에 맞춘다. 줄당 16자, 2줄, 초당 14자, 최대 7초. 최소 표시 시간만 지침의 5/6초 대신 1초로 더 보수적으로 둔다.
- 이전 기본값(20자·20 CPS)은 근거 없는 제안값이었다. 특히 읽기 속도 20자/초는 한국어 기준으로 통과시켜서는 안 될 자막을 통과시킨다.
- 지침은 OTT 번역 자막용이고 숏폼은 화면·글꼴이 다르다. 최적값으로 보지 않으며 다섯 값 모두 설정으로 노출한다. 실제 화면 측정 후 조정한다.
- 지침의 구·절 단위 줄 나눔은 반영하지 않는다. 한국어 절 경계 판정은 휴리스틱 위험이 커서 한계로 남기고, 문장 → 어절 → 글자 순서를 유지한다.
- 자막 싱크 보정(ffsubsync)과 별도 VAD 패키지는 추가하지 않는다. 전자는 쓸 자리가 없고, 후자는 faster-whisper가 내장한 Silero VAD를 이미 쓰고 있다.


## 화자 분리 연결과 검증 방식 (2026-09-18)

- 읽기 속도 기본값은 12자/초다. 지침 I부(일반 번역 자막)의 한도이며, 14자/초는 II부(SDH)에서만 허용하는 상향값이라 쓰지 않는다.
- 화자 분리는 WhisperX(pyannote)로 한다. 게이트 모델이라 `R4_HF_TOKEN`이 없으면 모델을 내려받기 전에 막는다. 토큰이 없는 설치에서도 나머지 기능은 그대로 동작한다.
- 화자 분리는 대본을 고치지 않는다. 최신 버전의 글자를 그대로 두고 화자만 붙인 **새 대본 버전**을 만든다. 기존 버전은 감사용으로 남는다.
- 자막에 겹치는 화자 구간이 없으면 화자를 비워 둔다. 가까운 화자를 추측해 붙이지 않는다.
- 화자 → 음성 연결은 자동화하지 않는다. 어떤 목소리를 쓸지는 사람이 고르고 `voice_assignments`에 버전으로 쌓는다.
- 기본값과 정렬 품질은 문서로 주장하지 않고 CI에서 잰다. 자막 줄 길이는 워커 이미지 안에서 libass로 그려 픽셀로 재고, 정렬은 문장 시각을 아는 합성 음성으로 오차를 잰다. 정렬 검증은 모델을 내려받으므로 라벨·커밋 표시가 있을 때만 돌린다.

## 2026-09-19: 자막 전용 번역 및 CI 준비 조건 수정

`audio_mode=subtitles`를 추가해 번역 이후 원본 영상 렌더로 바로 연결한다. 기존 원어 모드의 무료 동작을 유지하고, 번역의 비용 예약·재개 규칙을 공유한다. 립싱크는 dub 모드에만 허용한다. 편집기에서 구간을 선택해도 사용자가 선택한 제작 방식을 더빙으로 강제 변경하지 않는다.

pyannote CI 검증은 `HF_TOKEN`과 `verify-align` 라벨 또는 커밋 표시가 함께 있을 때 실행한다. 샘플 준비 단계와 소비 단계의 실행 조건을 맞춰 토큰만 등록된 일반 CI에서 샘플 누락으로 실패하지 않도록 한다.
