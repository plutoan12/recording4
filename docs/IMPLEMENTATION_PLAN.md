# 구현 계획

현재 모든 구현 항목은 미착수입니다. 이 계획은 사용자의 향후 구현 요청 후 실행합니다. 계정 개설, 유료 호출, 배포, 영상 공개는 해당 작업에 대한 사용자 지시 범위에서 진행합니다.

## 1. 요구사항 및 품질 검증

- [ ] PROJECT_BRIEF.md의 언어·처리량·예산·립싱크 필요 여부 확인.
- [ ] 대표 샘플 선정: 일반 발화, 배경음, 필요한 경우 다중 화자.
- [ ] YouTube OAuth와 API 프로젝트의 공개 업로드 제한 확인.
- [ ] YouTube Data API 쿼터와 하루 업로드 가능 편수, 상향 신청 절차 확인.
- [ ] STT·번역·더빙 결과 비교 및 오류 구간 기록.
- [ ] 영상당 처리 시간, 비용, 더빙 길이 오차 측정.
- [ ] 측정 결과로 더빙 길이 허용 오차·속도 조절 범위·재생성 횟수 확정.
- [ ] 월·작업당 비용 상한과 보관 기간 확정.
- [ ] 립싱크 후보를 짧은 샘플로 평가하고 필수/선택 여부 확정.

완료 기준: 사용할 언어·모델·음성, 품질 허용 범위, 비용 상한, 처리량 가정을 문서로 확정합니다. 샘플 실행에는 별도 서비스 자격증명이 필요합니다.

## 2. 기본 기반

- [ ] 저장소 구조, Python·Node 의존성 및 버전 고정.
- [ ] 관리 API, 프런트엔드, Docker Compose 개발 환경.
- [ ] 관리자 인증, DB 마이그레이션, 비밀 설정 예시.
- [ ] 원본 직접 업로드, 완료 검증, 파일 메타데이터 검사.
- [ ] 작업 생성·목록·상태 조회, DB 실행 요청과 큐 전달.
- [ ] 입력 해시 계산 규칙과 budgets·glossaries·voice_assignments 스키마 반영.

완료 기준: 로그인 → 원본 등록 → 워커의 파일 확인 → 관리화면 상태 표시가 연결됩니다. 미인증 접근과 잘못된 파일을 거부합니다.

## 3. 기본 영상 파이프라인

- [ ] 음성 추출, STT, 시간 정보가 있는 대본 저장.
- [ ] 번역·용어집 적용, 문장별 더빙과 길이 측정.
- [ ] 배경음 처리 방침 적용, 최종 자막 시간 정렬.
- [ ] FFmpeg 합성, 결과물 저장, 처리 단계별 로그와 비용.
- [ ] 공급자 연결을 모듈로 분리하고 요청·응답 ID 기록.
- [ ] 더빙 길이 정합 규칙 구현, 겹침 검사, 허용 오차 초과 구간 표시.
- [ ] 유료 호출 전 예산 예약과 완료 후 정산, 한도 초과 시 blocked 처리.

완료 기준: 대표 영상의 더빙·자막 결과물이 생성됩니다. 음성 누락, 잘린 영상, 원래 대사 중복, 구간 겹침, 자막 시간 오차를 검사합니다. STT·TTS 공급자 장애 시 실패 단계와 이유가 표시됩니다.

## 4. 검수·승인

- [ ] 원본·번역·최종 영상 비교 화면.
- [ ] 대본 편집, 선택 구간 재생성, 결과물 버전 관리.
- [ ] 승인자·승인 시각·승인한 파일 및 메타데이터 버전 기록.
- [ ] 수정 후 재검수, 반려 사유 표시.

완료 기준: 승인한 파일과 게시할 파일이 일치합니다. 승인 후 수정된 새 버전이 이전 승인으로 업로드되지 않습니다.

## 5. YouTube 게시

- [ ] 채널 OAuth 연결과 갱신 토큰의 서버 측 보관.
- [ ] 승인된 버전만 게시 요청을 만들도록 서버에서 검증.
- [ ] 이어 올리기 세션·진행 상태·영상 ID 보존.
- [ ] 제목·설명·필수 게시 설정, 한국 시간 입력과 UTC 변환.
- [ ] 비공개 업로드, 처리 상태 확인, 예약 공개 설정·조회.
- [ ] 게시 요청 중복 방지, 결과 불명확 상태의 복구.
- [ ] 게시 후 수정 경로: 메타데이터 수정과 영상 교체를 구분하고, 이전 영상이 공개 중이면 새 영상의 실제 공개를 확인한 뒤 전환.

완료 기준: 사용자 허가 범위 내의 테스트 채널·영상에서 예약 상태를 조회로 확인합니다. 공개 검증이 허가되지 않았으면 비공개 테스트까지 수행하고 그 한계를 기록합니다. 업로드 중 연결이 끊겨도 같은 세션을 조회·재개합니다.

## 6. 운영 보강과 립싱크

- [ ] 워커 재시작, Redis 재전달, 중복 요청, API 시간 초과 복구 검증.
- [ ] 작업 시간 제한, 비용 상한, 동시 실행 수, 임시 파일 정리.
- [ ] DB 백업·복구, 저장소 보관 기간, 정체 작업 알림.
- [ ] 보관 기간 만료 삭제와 원본 삭제 요청 시 파생물 연쇄 삭제.
- [ ] 립싱크 선택 단계와 실패 시 재시도·건너뛰기 정책.
- [ ] 배포·롤백 절차와 운영 가이드 작성.

완료 기준: 단계 재실행으로 불필요한 유료 호출·영상 중복 게시가 발생하지 않도록 검증하고, 외부 API 결과가 불명확한 사례는 자동 처리 한계와 수동 복구 절차를 명시합니다.

## 테스트 전략

- 외부 공급자 연결은 인터페이스로 분리하고 테스트에서는 기록된 응답으로 대체합니다. 실제 유료 호출은 그렇게 표시한 테스트에서만 수행합니다.
- ARCHITECTURE.md의 상태 전이표를 그대로 테스트합니다. 표에 없는 전이가 거부되는지도 확인합니다.
- 같은 입력 해시로 두 번 실행해 유료 호출이 한 번만 발생하는지 확인합니다. 큐 재전달과 워커 강제 종료를 재현합니다.
- 여러 워커가 동시에 예산을 예약해 한도를 넘지 않는지 확인합니다. 정산되지 않은 예약의 만료 회수도 재현합니다.
- 실패 주입: 공급자 시간 초과, 업로드 중단, 응답 유실, 한도 초과를 각각 넣고 복구 경로와 남는 상태를 확인합니다.
- FFmpeg 산출물은 바이트 비교 대신 ffprobe로 길이·트랙 구성·구간별 음성 존재를 검사합니다. 인코더 버전에 따라 결과 바이트가 달라집니다.
- 더빙 길이 오차와 자막 시간 오차는 수치로 검사합니다. 구간 겹침은 0건이어야 합니다. 육안 확인만으로 완료로 보지 않습니다.
- YouTube 연동은 테스트 채널에서 비공개 업로드까지 수행합니다. 허가되지 않은 공개 검증은 제외하고 그 한계를 기록합니다.

## 구현 시 제안하는 디렉터리

아래는 미래 구조이며 아직 생성하지 않았습니다.

```text
apps/web/               # React 관리화면
services/api/           # FastAPI, 인증, 승인, 게시 요청
services/worker/        # Celery, FFmpeg, 업로드
packages/pipeline/      # 데이터 형식, 단계 로직, 공급자 연결
migrations/             # PostgreSQL 마이그레이션
tests/                  # 상태 전이·실패 복구·통합 검증
infra/                  # Compose, 배포 구성
.github/workflows/      # 테스트·배포
docs/                   # 설계·운영·인수인계
```

## 향후 병행 작업 구분

1단계(샘플 측정)와 2단계(기반 구축)는 병렬 진행할 수 있습니다. 2단계는 언어·모델 확정을 기다릴 필요가 없습니다. 기반 계약과 데이터 모델을 먼저 합의한 뒤 관리화면, AI 파이프라인, 게시 기능을 별도 브랜치로 나눌 수 있습니다. 담당자는 고정하지 않습니다. Codex와 Claude가 실제로 작업을 시작할 때 HANDOFF.md에 담당 브랜치·파일·의존성을 기록합니다. 공통 스키마 변경은 선행 합의가 필요합니다.
