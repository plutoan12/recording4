# 실제 음성 → 단어 강조 자막

Mac의 기존 로컬 워커 이미지와 캐시된 Whisper small 모델을 사용해 실제 음성 시각을
세로형 자막 생성기에 연결했습니다. Docker Desktop이 실행 중이어야 합니다.
기존 API/워커 서비스를 변경하거나 재시작하지 않고 별도 일회성 컨테이너를 실행합니다.

## 실행

프로젝트 루트에서 자동 전사와 영상 생성:

```sh
sh scripts/make_audio_captions.sh /절대경로/녹음.wav .runtime/my-audio-captions
```

교정한 UTF-8 대본을 실제 발화에 맞춰 정렬:

```sh
sh scripts/make_audio_captions.sh /절대경로/영상.mp4 .runtime/my-aligned-captions \
  --script /절대경로/대본.txt --language ko --style marker-follow
```

출력 폴더는 새 이름을 사용합니다. `--style clean-focus|marker-follow|soft-pop`,
기존 15종 포인트 색상인 `--theme`, `--fonts`를 지원합니다.
대본은 시간코드 없는 일반 텍스트이며 SRT 파일 자체를 넣으면 안 됩니다.
문장 줄바꿈은 보존하지 않고 화면 폭·발화 간격·구간 길이에 맞춰 자동 재분할합니다.

## 두 처리 방식

- 대본 없음: faster-whisper가 전사하면서 단어 시각을 계산합니다. 오인식한 대사는
  대본으로 교정해 `--script`로 다시 정렬하세요. JSON의 글자만 수정하면 시간은 재계산되지 않습니다.
- 대본 있음: stable-ts가 입력 대본을 음성에 맞춥니다. 출력 글자가 대본과 다르면 실패합니다.
  음성에 없는 대본을 넣어도 모델이 시각을 만들어낼 수 있으므로, 텍스트 보존 검사는 정확도 인증이 아닙니다.

모델 서브 토큰은 원문 어절로 합치되 실제 시작·끝을 사용합니다. 어절 경계를 가로지르는
토큰은 균등 분할하지 않고 오류를 냅니다. 0 길이·겹침·역전·비정상 수치·오디오 범위 초과도
거부합니다. ASS의 1/100초 정밀도에 맞춰 최대 약 5ms 반올림합니다.
6어절·약 3.5초·600ms 이상 휴지·문장부호·실제 폰트 폭을 기준으로 표시 구간을 나눕니다.
단일 어절 자체가 3.5초를 넘는 경우 시간을 잘라내지 않고 그대로 둡니다.

## 결과

- `preview.mp4`: 실제 입력 음성이 포함된 1080×1920 강조 자막 영상.
- `editable.ass`, `captions.srt`, `captions.vtt`: 모션 자막 및 일반 문장 자막.
- `words.json`: 단어별 시각, 공급자·모델·언어·처리 모드, 원본 SHA-256.
- `raw-alignment.json`: 모델이 반환한 원래 토큰/시각. 문제 분석용.
- `report.json`, `fonts/`: 출력 조건 및 폰트 라이선스.

MP4는 어두운 배경의 자막 미리보기입니다. 입력 영상 화면을 합성하는 기능은 아닙니다.
음성은 분석용 16kHz 모노로 변환한 뒤 AAC로 포함합니다. 최종 작품에서 원음의 스테레오·음질을
유지하려면 편집기에서 원본 음원과 ASS 렌더 결과를 사용하세요.

## 실행 환경

- 호스트: `.venv-converter`, 기존 Pillow/pysubs2/imageio-ffmpeg.
- 일회성 공급자: `recording4-stack-worker` 이미지, `recording4-stack_models` 모델 캐시.
- 기본 모델: 캐시된 `small`, CPU int8. `--image`/`--cache`/`--model`로 환경 지정 가능.
- `--network none`, `HF_HUB_OFFLINE=1`. 원음을 외부 API로 보내지 않으며 유료 호출하지 않습니다.
- 모델 캐시는 읽기 전용입니다. 새 모델을 지정하려면 미리 해당 캐시에 준비해야 합니다.
- 이미지·캐시가 없는 다른 컴퓨터는 기존 워커 설치가 먼저 필요합니다. 변환기 설치 스크립트만으로
  STT 모델과 Docker 이미지가 설치되지는 않습니다.

현재 연결 범위는 로컬 CLI입니다. 관리화면/API의 버튼에 새 출력 경로를 붙이지는 않았습니다.
자동 번역·화자 분리는 이 명령에서 실행하지 않습니다. 겹치는 음성과 긴 음악 구간은 별도 검수가 필요합니다.

## 실제 검증 (2026-09-20)

이전에 받은 한국어 사람 목소리 샘플 `.runtime/new-ko-speech/human0.wav`로 실행했습니다.

| 처리 | 결과 | 출력 |
|---|---|---|
| 자동 전사 | 4개 표시 구간, 18어절 | `.runtime/audio-caption-asr-01` |
| 입력 대본 정렬 | 4개 표시 구간, 19어절, 대본 글자 보존 | `.runtime/audio-caption-aligned-01` |

각 영상 전체 디코딩 성공, 실제 AAC 음성 스트림 추출과 비무음 RMS 확인,
약 12.7초의 오디오 보존 확인. 정렬 영상 프레임에서 한국어 두 줄 배치·현재 단어 강조 확인.
각 폴더 verification.json에 측정값을 기록했습니다.

관련 독립 테스트 90개, 대상 Ruff 통과. 전체 서버 테스트 및 편집기 네이티브 가져오기는 미실시.
샘플에 단어별 외부 정답이 없어 단어 정렬 정확도 수치는 산출하지 않았습니다.
자동 전사 18어절과 대본 19어절의 차이는 두 결과가 같은 전사 정확도를 갖지 않음을 보여줍니다.
생성한 타이밍도 사람이 듣고 교정해야 하며, 기능 실행 검증과 정확도 인증을 구분합니다.

## 웹 편집기·원본 화면 합성 확장

`ClipEditor`의 **음성에 맞춘 단어 강조**에서 효과와 음성 언어를 고릅니다.
선택 구간에서 말한 내용만 대본에 넣거나 비워 두고 **숏폼 렌더**를 누릅니다.
새 경로는 선택 구간의 원음을 추출해 정렬하고, 원본 영상에 ASS를 입힙니다.
일반 자막 편집 표의 큐는 이 모드에서 사용하지 않습니다. 일반 자막을 쓰려면 효과를
‘일반 자막’으로 선택합니다. 번역·더빙 단계 전송은 기존 일반 자막 경로입니다.

API는 기존 `POST /clips`에 아래 선택 필드를 추가했습니다.

```json
{
  "caption_effect": "marker-follow",
  "caption_script": "선택 구간에서 실제로 말한 대본",
  "caption_language": "ko"
}
```

기본 caption_effect는 none이며 기존 렌더 동작을 유지합니다. 단어 강조 출력은
1080×1920입니다. 작업 완료·실패·재시도·미리보기·버전 승인도 기존 작업 흐름을 사용합니다.
정렬 JSON과 ASS는 작업/시도별 저장소 키에 함께 저장하며, 현재 웹 다운로드 링크는 MP4용입니다.
시각은 전체 원본 시간이 아닌 선택 구간 시작을 0으로 한 상대 시각이고 원본 시작을 메타데이터에 기록합니다.

워커 이미지에는 `.[templates]` 의존성을 추가했습니다. 운영 배포 시 API·웹·워커를 함께
갱신해야 합니다. 현재 실행 중인 서비스는 별도 checkout `recording4-caption-delivery`의
다른 버전이므로 **그 서비스에는 아직 반영하지 않았습니다**. 기존 서비스 교체 없이
`recording4-caption-preview:local` 일회성 이미지에서 이번 recording4 소스를 검증했습니다.

검증: 웹 TypeScript/Vite 빌드, API·편집·렌더·단어 정렬 관련 46개 및 기존 정렬·화자 API
19개 테스트 통과. 실제 한국어 음성+움직이는 테스트 패턴 영상으로 12.72초
1080×1920 합성 완료. 전체 디코딩, 비무음 AAC(-33.4dB 평균), 단어 강조 프레임 확인.
출력 `.runtime/word-overlay-check/output.mp4`. 웹 화면의 실제 브라우저 조작과 운영 반영은 미실시입니다.
